# 模块字典声明

纯 Java 21 元数据 API，生产运行时无 Spring、JPA、RPC、JSON 库或业务实现依赖。
模块选择 `@ModuleDictionaries(Definitions.class)`；定义类实现 `DictionaryDefinitions`，
使用公开无参数构造器，只返回不可变声明，不读取环境、不连接服务、不执行写入。

## 声明与拥有方

`DictionaryContribution` 保留模块、贡献键、版本、执行优先级和有序字典。
`DictionaryDeclaration` / `DictionaryItemDeclaration` 仅声明编码、值、名称、翻译键、描述和排序，
不接受持久化 ID、租户、审计字段、启停状态或可执行代码。
每批最多 64 个字典、每字典 1024 项、合计 4096 项；字符串按 Unicode 码点限长，
拒绝空必填字段、NUL、未配对代理字符、重复编码和值，以及会被持久层改变的值首尾空白。

组合规划按选中模块读取元数据，校验声明模块与实际模块归属一致。
不同模块声明相同字典编码会拒绝规划，跨宿主分配也不能绕过。
声明内容、字典顺序和稳定初始化身份不随物理宿主变化。

## 当前接入与兼容边界

- OIDC / notification API 工程拥有各自定义；没有为字典注册引入身份实现依赖。
- Common 原初始化器作为旧宿主适配器使用同一声明，通过身份领域的 `DictionaryDeclarationWriter` 在同一写事务中应用整份声明，内部复用 `BuiltInDictionaryRegistrar`。
- 保留旧贡献键、版本、checksum、优先级及字典/选项内容。旧适配器仍按既有行为刷新元数据并设 `enabled=true`。
- 声明本身没有授权含义。`moduleCode` 不是受信服务身份，不能用于放行远程写入。
- 注册契约及模块初始化器位于独立的 `simplepoint-platform-dictionary-registration`，本 API 仍无 RPC/框架依赖。OIDC/通知已声明初始化器；身份模块提供经安装批准的应用及持久回执。

## 后续必须完成

1. 将已实现的纯安装计划与身份领域本地安装端口接入正式安装器，完成凭据预置、配置发布、旧实例退出和运行期切换。
2. 将已实现的旧 Common 登记与字典数据接管端口接入安装器。普通安装遇到未管理数据仍拒绝自动认领；显式接管保留完整数据和管理员修改，缺失必要字典/选项要求先处理，不能因为新登记空间为空就重放历史初始化。
3. 在已通过的隔离本地调用、JSON 分派、真实 PostgreSQL 并发/回滚/升级测试之外，补齐正式 HTTP 网络和三拓扑部署验收，再移除兼容适配器。

详见[注册契约与安装边界](../simplepoint-platform-dictionary-registration/README.md)。

## 验证

API 测试覆盖边界、Unicode、不可变集合和 JSON 往返；组合测试覆盖选择、换宿主与跨宿主编码冲突。
Common 的 `DictionaryDeclarationCompatibilityTest` 使用修改前已安装产物采集的固定基线，
比较创建和刷新路径的全部元数据及登记键。基线不是从新声明生成的期望值。

## 身份领域写事务

`DictionaryDeclarationWriter.apply` 是身份内部的本地能力，不是 RPC 提供方。
它在读取字典前进入 `DictionaryCatalogWriteBoundary`，整份声明的字典和选项与目录修订号一起提交/回滚。
管理服务的单条/批量新增、修改、删除及全部删除使用同一边界；批量新增保留单条字段校验和默认值，
字典删除先清理对应选项，重命名在修改前保留旧编码以更新选项归属。

底层 `simplepoint-data-jpa` 的 `CatalogWriteBoundary` 与资源目录共用：
锁由拥有方数据库的唯一修订行提供，多实例同样生效；同一物理事务只进入一次。
缺少写事务、只读事务或进入前已经加载目录实体的上下文会被拒绝；不会清理脏实体来掩盖过期读取。
更新锁行使旧 repeatable-read 快照无法等锁后继续覆盖；异常和超时不自动重放。
公共错误保留 `DICTIONARY_WRITE:*` 诊断码及 `dictionaries.write.*` 中英文翻译键，SQL 和原因链不返回浏览器。

### 部署前置条件

必须先执行 identity 的 V6 目录锁、V7 注册权威及 V8 旧数据接管迁移，新增独立锁行和登记表，不修改字典/选项或启停状态。
新模块迁移清单已经包含 V6–V8；旧宿主升级仍需由安装流程受控执行迁移，再切换应用版本。
缺表/缺行会拒绝写入，禁止静默绕过。运行新旧写入方的混合版本不能保证串行化，旧实例必须退出。

新字典注册将持久完成状态与字典修改放在身份拥有方同一事务中，不另行调用远程 bootstrap 登记。
相同声明的重试及换宿主不重新刷新元数据，因此保留管理员修改；声明升级仍按声明刷新。
历史拥有方的显式接管端口已实现；正式安装/拓扑切换编排尚未完成，不能将纯规划或提供方测试视为已自动上线。
