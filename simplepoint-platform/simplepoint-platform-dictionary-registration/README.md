# 模块字典注册

仅依赖字典元数据、纯组合规划及 remoting 契约。生产运行时不依赖 Spring、JPA 或身份领域实现；
`verifyDictionaryRegistrationDependencies` 保持该边界。身份提供方和数据库事务属于 identity。

## 两个独立入口

- 运行时仅公开 `security.dictionary-registration:1` 的 `apply(DictionaryContribution)`，不导出安装或管理 CRUD。
- 受信安装流程使用身份领域的本地 `DictionaryRegistrationStore.install`；运行时客户端不能自批权限。

`DictionaryRegistrationPlan.prepare` 从完整部署计划、显式已有世代和本次操作 UUID 派生批准命令。
客户端身份与资源注册共用 `ModuleClientPlan`，绑定逻辑模块和本次部署，不因换宿主改变模块归属。
提供方验证 OAuth 服务身份与数据库中的当前批准，不相信请求中的模块名称或普通用户同名账号。
契约强制隔离本地调用，不能因合并 JVM 跳过身份验证或继承调用方事务。

## 安装与应用

1. 安装器执行 identity V6–V8 迁移，预置当前操作的模块客户端及凭据。
2. 读取已有世代，准备完整批准批次。命令要求预期世代匹配、操作内模块/客户端唯一。
3. 身份拥有方在目录锁事务内写操作指纹、字典编码拥有方和新世代批准。整批重试必须内容相同且仍是当前世代；子集、修改后的批次、过期操作及复用旧客户端均拒绝。
4. 模块初始化器按声明优先级在 BOOTSTRAP 阶段通过固定模块客户端调用。声明的版本化 SHA-256 指纹包含全部元数据、空值及顺序，必须精确匹配批准内容。
5. 字典/选项写入与完成状态在同一数据库事务提交；随后返回操作、世代和内容指纹回执。事务回滚不留下已完成状态，响应丢失后的显式重试返回持久结果。

以上第 1–3 步是安装器接入协议；**正式安装器的凭据预置、配置发布和运行切换尚未接入**。
纯计划不会写数据库或自动授予权限，生产启动不能跳过批准。

无需在字典事务前后另行调用远程 bootstrap 的 RUNNING/SUCCESS 登记；字典拥有方的持久完成即权威，
避免引入两个数据库之间的完成窗口。契约没有开启通用传输自动重试；显式重试及重启调用已具备持久幂等语义。

## 更新、退出与管理修改

- 最新已完成内容与新批准相同：沿用完成状态，换宿主或重新上线不覆盖管理员修改的名称/启停状态。
- 内容改变：新世代应用一次声明；当前兼容应用逻辑会刷新声明元数据并启用声明中的字典/选项。
- 退出：使用空声明/空客户端的退休命令，增加世代，拒绝旧客户端；保留字典、历史和编码所有权。
- 管理端可以调整元数据与启停状态，但不能删除已管理字典、改变其编码，或抢先创建已预留编码。
- 未管理的现有字典、软删除行及孤立选项均要求显式接管；不会自动认领、清除或重新启用。
- 兼容初始化器遇到已批准/退休模块或已认领编码会拒绝。部署必须退出旧二进制写入方，旧二进制不具备新边界保护。

## 验证与未完成边界

覆盖纯计划/初始化器、整批批准重试、代码所有权、声明越权、事务回滚、并发、进程内对象重建、
退休/重新上线、管理覆盖保留及真实签名 JWT。H2 和隔离 PostgreSQL 使用实际 JPA/事务及 V6–V8 SQL；
隔离本地路由与 JSON dispatcher 拒绝安装方法、错误签名/受众/scope、用户授权和撤销令牌。

这些测试没有启动正式 HTTP 网络、安装器或三套真实部署。旧登记和字典数据的本地接管端口已实现，
已提供独立安装日志及字典适配器，正式部署的完整编排和 standalone 仍待完成。升级前必须先执行迁移；此增量不修改业务环境。

## 旧字典数据接管

身份领域的 `DictionaryLegacyAdoptions` 是本地安装能力，不进入注册 RPC。接管命令位于纯契约包，
身份实现不依赖 bootstrap-registry 的代码或持久化表。安装流程负责跨拥有方衔接：

1. 停止旧初始化执行者并退出旧写入版本，执行 bootstrap-registry V2、identity V8 及此前迁移。
2. 使用已确认的历史发布声明调用字典 `preview`。预览读取该声明全部编码及全部现存选项，包含审计、停用、软删除、自定义选项；最大 64 个字典、8192 个选项。原始标量查询不受请求软删除过滤影响。
3. 在 registry 中将同一贡献的成功登记接管到 `owner/identity/dictionary`。保留操作 UUID 和完整回执；版本、旧 checksum 和贡献键必须与历史声明一致。
4. 安装器从真实回执构造 `LegacyCompletion`，调用字典 `adopt`。提供方持目录锁复核数据指纹，原子写入所有编码归属和接管回执，**不修改字典或选项的任何字段**。
5. 执行正常部署批准。没有后续已完成版本时，批准继承相同声明的接管完成状态，首次运行不会重新刷新或启用历史数据；存在后续已完成版本时以最新实际完成为准，不能用旧接管状态跳过升级/回退。

缺少声明中的字典/必要选项、已有其他拥有方、已有部署批准或预览后数据变化均拒绝。
显式接管可保留软删除行；这不等于运行时重新提供被删除的选项，也不自动修复用户删除的数据。
新增自定义选项及管理员覆盖保留，后续同内容重试/换宿主仍不刷新它们。

`LegacyCompletion` 是受信安装器输入，不能凭一个可自行构造的 DTO 认定来源已获认证。
安装器必须从 registry 的实际持久回执取得它；旧 checksum 仅是历史版本标签，不能证明任意新声明
就是历史发布内容。声明来源核验、自动身份映射、操作持久化与旧客户端撤销仍须由正式安装器完成。

两处提交独立：registry 退役成功、字典接管失败时，保留已退役状态；修复原因后使用同一回执继续。
字典接管成功但响应丢失时，重复相同命令返回持久结果，不重写后来发生的管理员修改。
不得通过删除退役记录恢复旧初始化，也不能把字典接管完成当作凭据、部署批准或业务就绪已完成。

### 安装执行适配

[`simplepoint-platform-installation-dictionary`](../simplepoint-platform-installation/README.md) 已将 registry 退役与字典接管接入同一不可变操作计划。
它通过拥有方的只读 `findCompletion` 获取真实回执并转换，日志独立记录两步的尝试和完成；
源提交后丢失日志确认、目标失败及重启后的恢复有三库验证。
正式安装入口仍须保存并验证原始输入、发布产物来源及退出旧执行者，不能把此接管子流程当作整个部署完成。

### 安装端口依赖

`DictionaryLegacyAdoptionPort` 提供纯 Java 的预览、接管和只读完成查询契约，不带远程导出注解。
身份领域的 `DictionaryLegacyAdoptionAdapter` 调用既有拥有方事务代理；安装库只依赖接口与 DTO。
这样安装编排可独立测试和复用，领域仍保有目录锁、原子写入、回滚及历史数据保护。
