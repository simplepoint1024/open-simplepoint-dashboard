# 资源目录注册边界

资源目录由 identity 拥有。`ResourceRegistrationService` 是声明注册的 RPC 契约，
由独立的 `ResourceRegistrationProvider` 提供；`ResourceService` 保留本地资源管理职责，
不再继承 RPC 契约。宿主改变不得改变资源拥有方、资源 ID 或已有授权。

## 调用方授权与配置派生

注册契约为 `security.resource:3`。入口通过 `ServiceClientIdentity` 提取已认证 OAuth 客户端，
必须是 `client_credentials` 且具有 `service-router.invoke` scope。`syncRegistered` 在目录写事务中
读取持久世代，核对当前获准客户端，再修改资源；请求不能携带或选择客户端身份。

拥有方从未被安装器接管时，才使用下面冻结的显式兼容策略；未匹配默认拒绝。接管或停用后以持久状态为准，
旧进程中的静态策略不能恢复旧客户端权限。空清单和 null 清单也执行世代校验。
详细身份生成、精确重试与升级流程见[资源注册部署世代](../../../doc/design/resource_registration_deployments.md)。

```properties
simplepoint.rbac.resource-registration.owner-clients[workflow]=simplepoint-module-workflow-http
```

以上为模块模式的示例。安装侧通过 `ModuleResourcePlan.registrationClients(deployment, clientOverrides)`
从完整部署计划生成拥有方到客户端的映射，运行期凭据装配与安装规划共用 `ModuleClientPlan`。
模块改放到另一宿主不会改变身份。规划拒绝同宿主和跨宿主共用客户端 ID，包括未拥有注册资源的模块，
以及未选模块的身份覆盖。规划 API 不创建凭据、不发布配置；正式安装器接入仍待完成。

兼容策略启动时校验并冻结，不使用通配符、不从 classpath 中所有模块推断信任，不因配置对象被修改而扩大权限。
策略变更须随受控部署重新装配。compose 的 Common 配置保留各旧服务的明确身份映射；dev 配置仅保留
原开发模式的单客户端兼容。模块宿主必须使用生成的模块策略，不能复用旧宿主凭据。

契约声明 `isolateLocalCalls=true`，旧宿主即使配置 `consumer.local-isolation=false` 也必须进入
隔离调用。资源服务器的本地认证适配器验证出站服务令牌，浏览器身份和调用方事务不继承；缺少认证适配器
时提供方仍拒绝请求。真实 HTTP 请求进入同一提供方策略。其他没有声明此约束的旧契约保留原兼容行为。

插件安装器仍通过 identity 内部的 `ResourceService.sync` 执行受控本地安装，复用完整快照校验和原事务。
该接口不注册为 RPC，不是远程认证的本地绕过分支；不能让其他领域通过直接注入它替代已声明的 RPC。

## 完整快照校验

`ResourceRegistrationPlan` 在写入任何资源、祖先关系和授权之前准备整个快照：

- 每个资源必须有稳定代码；代码、非空路径在整个树内唯一。
- 同时检查代码和路径对应的旧记录，不能以其中一个匹配掩盖另一个冲突。
- 匹配的旧记录必须属于相同拥有方。未归属的旧记录也不能被隐式接管；应先完成受控迁移。
- 两个声明不能用旧代码和旧路径分别认领同一记录。同一拥有方通过原路径改名可保留 ID；
  同时修改代码和路径无法推断原记录身份，应走单独的显式迁移。
- 声明的 `pluginId` 不能覆盖快照拥有方。父资源引用必须属于同一拥有方且保留在当前快照。
  嵌套树和已有父 ID 引用共同参与拓扑排序、循环检测、深度及作用域检查。
- 最多 10,000 个资源、64 层。直接本地调用的循环对象和重复对象引用也会被拒绝。
- 外部模块的后代使其祖先受到保护：不能通过删除、移动或变更祖先作用域间接影响这些后代。
- 清理时额外核对祖先关系表的实际删除范围，防止旧关系误删保留资源或其他拥有方资源。
  资源及祖先关系在同一事务删除；晚期拒绝会回滚前面的更新。

输入 DTO 不被修改。未提供权限元数据时保留现有描述。空快照沿用兼容的“不操作”语义，
不能用于卸载模块。卸载、拥有方转移和改码迁移不是同一操作。

拒绝使用 `RESOURCE_REGISTRATION:*` 稳定诊断代码和 `resources.registration.*` 翻译键，
不将提交的资源、权限描述等内容拼入公开错误。相同契约解码器用于本地/远程错误语义。

## 目录写入事务

`ResourceCatalogWriteBoundary` 使用 identity 数据库里的 `simpoint_resource_catalog_revision`
单例行。首次进入写事务时原子增加版本，数据库行锁一直保持到提交或回滚；空目录也受保护。
资源代码、路径和跨拥有方祖先关系共享一个命名空间，因此当前使用一个目录写入边界，读取无需取该锁。
这不要求其他领域共享 identity 数据库，也不使用平台管理员状态表或进程内锁。

- 资源注册、单条/批量新增、修改、单条/批量/全部删除及按拥有方卸载均进入相同边界。
  批量新增和删除复用资源领域处理，不能退回父类绕过祖先关系和授权处理。
- 插件贡献处理在查询、校验或写入目录之前进入；安装时在锁内再次校验，卸载调用
  `removeByOwner`，保护外部拥有方的后代。插件其他领域效果仍遵守各自原有事务，不宣称整个插件生命周期原子。
- 已加入该边界的嵌套操作复用锁，并随外层事务一起提交/回滚；不另开事务提前提交资源。
  事务结束后标记自动结束，事务挂起时随 Spring 同步上下文一起挂起。
- 没有活动写事务、只读事务，或首次进入前已经加载 Resource / ResourceAncestor / MicroModule
  的 JPA 上下文会被拒绝。内部聚合操作必须先 `enter()` 再读取目录；不能在预先读过目录的
  外层事务或长生命周期持久化上下文里直接调用写入口。拒绝时不会清空缓存或自动丢弃未提交编辑。
- 版本行执行真实更新，避免旧 repeatable-read 快照在等到锁后继续使用旧视图。
  更新等待设有 10 秒查询超时；超时、序列化冲突、缺表/缺行和版本耗尽均拒绝写入，不自动重放。
  `CATALOG_CONTEXT_CONFLICT` / `CATALOG_UNAVAILABLE` 使用稳定错误代码和中英文翻译。
- 此版本表示已提交的目录写事务顺序，**不是部署版本**。旧应用在新应用之后拿到锁，仍可能提交旧声明；
  该行为由 V5 的持久部署世代约束。直接 SQL 或绕过领域服务的内部写入不属于受保护路径。

### 安装与升级

模块安装使用 identity 的 V4 目录版本和 V5 部署世代迁移，迁移清单自动发现这些贡献。
跟踪到 V3/V4 的数据库按正式迁移器升级；迁移不修改业务资源或授权，也不会重置已安装版本行。
旧的未纳入模块迁移历史的数据库仍需受控接管，不能以跳过历史校验来执行完整基线。
迁移前应停止所有旧目录写入实例，再协调启用新写入方；新旧实现混跑不具备完整串行化保证。
运行账号不会临时创建或补齐锁表，缺少迁移使资源初始化失败。此轮没有对运行环境应用迁移。

## 尚未完成的运行期保护

调用方校验、快照检查与数据库串行化仍不能替代完整安装和升级协议：

1. 正式安装器须发布已派生的拥有方策略、创建对应客户端并安全分发凭据。新提供方和配置必须协调部署；
   缺少策略或旧宿主没有有效出站服务凭据时，必需资源初始化会失败。修改仓库中的 profile 文件不等于
   已更新运行中 Consul 配置。实际旧服务冷启动及完整 OAuth/浏览器验收尚未完成。
2. 持久串行化已接入当前资源领域写入。仍需随正式部署检查全部旧写入方停用、长期持久化上下文、
   实际插件启停、超时后的运维恢复以及多进程升级；其他独立管理路径（例如前端 remote 的普通 CRUD）
   不因资源目录锁而自动获得新的并发协议。
3. 持久世代、批量激活/停用和新客户端规划已接入；安装器实际创建秘密、发布全领域策略及撤销旧客户端仍待完成。
   全部旧 v1/v2 提供方及绕过新检查的旧二进制必须退出。当前不自动转移数据或恢复授权。

在以上项目完成并通过真实部署验证前，不能将这次快照校验称为完整的跨宿主注册安全保障。

## 验证

- `ResourceRegistrationPlanTest`：代码/路径碰撞、拥有方、完整快照、层级/作用域、边界与循环对象。
- `ResourceServiceImplTest`：写前拒绝、陈旧关系的删除保护、原有导航回归。
- `ResourceRegistrationTransactionTest`：实际 JPA Repository 和 Spring 事务代理，验证改名、退役、
  祖先关系清理和晚期拒绝回滚。默认 H2；也支持专用 PostgreSQL 测试库。
- API 的 `ResourceRegistrationBoundaryTest`：JSON dispatcher 保留约定的错误代码。
- `ResourceRegistrationProviderTest`：真实属性绑定、兼容策略、已验证客户端传递及不接受用户身份。
- `ResourceRegistrationDeploymentTest`：真实世代状态和资源事务、CAS 竞争、停用后拒绝、批量摘要、精确重试/过期重放、回滚和 JSON v3 错误；管理端口和旧协议均不导出。
- `ResourceRegistrationSecurityTest`：真实签名 JWT、本地隔离、同一提供方 JSON dispatcher，验证
  浏览器上下文隔离、身份/签名/scope/audience/撤销失败及不导出本地管理方法。域写入是明确的 mock；
  不冒充外部 OAuth 服务和真实 HTTP 网络验收。

PostgreSQL 测试会建表并删表，仅允许专用地址
`jdbc:postgresql://127.0.0.1:45436/resource_registration_test`；通过
`SP_RESOURCE_TEST_POSTGRES_URL` 和 `SP_RESOURCE_TEST_POSTGRES_PASSWORD` 启用，账号为 `resource_test`。
事务测试使用真实 V4/V5 脚本初始化目录版本与世代历史，其余表由测试 ORM 建立。
`ResourceCatalogConcurrencyTest` 在同一 JVM 的独立服务实例与真实数据库事务之间验证竞争、
回滚、旧快照、缺失迁移和插件贡献；其他授权/租户合作者仍为明确替身，不声称完成外部网络或浏览器验收。
实际模块迁移另由 `IdentityModuleMigrationPostgresTest` 验证 V3/V4 → V5、重入、不恢复已撤销授权，
并在共享/独立存储装配中核对锁绑定 identity 的数据库。
