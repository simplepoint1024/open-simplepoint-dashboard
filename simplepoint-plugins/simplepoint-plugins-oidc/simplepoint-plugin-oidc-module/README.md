# OIDC 模块存储

领域聚合包只包含 API、持久化和服务实现，不再携带浏览器控制器。需要管理 API 的宿主依赖
`simplepoint-plugin-oidc-rest` 并选择 `oidc-http`，它自动包含本地 `oidc` 领域依赖。
Common 旧服务已显式依赖 REST 产物；完整接入边界见[Common 可选 HTTP 适配](../../../doc/design/common_http_adapters.md)。

`oidc` 拥有客户端、授权令牌、用户同意和外部身份关联的五张控制表。客户端、
令牌及同意适配器均在 OIDC 的本地事务中工作；读取使用只读事务。通过
`@EnableModulePersistence` 组合时自动使用 OIDC 的存储绑定，不要求开发者给每个
仓储或服务重复配置数据库。身份账户与 MFA 设置由 `identity` 拥有。

首次注册保留调用方提供的 RegisteredClient ID；按 clientId 重注册保留数据库中的
既有 ID 与创建审计信息，避免中断令牌和同意记录的引用。新 clientId 不允许占用
其他客户端已有的 ID。配置更新可显式清空密钥，应用层仍须配置合适的认证方式。
外部绑定持久化由本模块的 `ExternalIdentityAccountService` 拥有；浏览器只负责会话与
身份核对，不直接使用仓储或开启数据库事务。此本地接口不构成新的 RPC 能力，
完整 OAuth HTTP 入口仍需在后续宿主适配工作中装配和验收。

## 版本化安装

- V1 保留初始映射，已建立的校验和不重写。
- V2 取消客户端签发时间、密钥的单列唯一约束，并允许密钥为空；公有客户端的
  授权码/PKCE 配置因此可以持久化。同一时间注册多个客户端不再冲突，
  `client_id` 唯一性与原有主键继续保留。
- V2 只处理当前目标表上指定字段的单列 UNIQUE 约束，不猜测 Hibernate 生成的
  约束名，不改写客户端、授权令牌或同意记录。

- V3 将外部绑定的“提供商 + subject”“提供商 + 用户”唯一性改为仅约束未撤销记录。
  解绑保留历史行，重新绑定创建新 ID；旧绑定引用不能更新新行。V1/V2 不重写。

使用模块迁移安装的新库自动执行 V1、V2、V3；已有模块历史的库仅执行尚未完成的版本。
没有模块迁移历史的旧服务数据库仍须通过整体计划中的受控接管流程。
不要在旧库运行 V1、修改历史校验和或开启 Hibernate 自动更新来代替接管。
若需在旧服务提前使用无密钥客户端，应先安排经过备份和结构核对的 V2 升级；
新版外部绑定写入逻辑还要求先完成 V3，再切换全部绑定写入节点；不依靠新旧写入代码
混跑来保证历史/并发语义。此文档及代码变更没有操作当前业务数据库。

同一存储组的调用参与同一本地事务，独立存储组分别提交；不提供跨库原子事务。
迁移和服务回归的 PostgreSQL 测试位于 `simplepoint-platform-composition-verification`，
覆盖批量注册、令牌查找、同意更新/删除、回滚、升级保留和跨 schema 隔离。

## 外部账号绑定边界

- 调用方必须先验证外部 subject 与本地账户。浏览器适配器拒绝删除、禁用、锁定或
  过期账户；创建绑定后再次读取身份状态，再记录成功登录。独立存储不提供全局原子性，
  核对期间账户变化会拒绝登录；不能据此宣称并发停用与登录之间存在跨库串行保证。
- 新绑定/解绑及提供商修改/删除锁定提供商行；批量提供商删除按 ID 固定顺序加锁。
  常规登录只锁定对应有效绑定行，不让所有登录串行通过一个提供商锁。
  数据库部分唯一索引继续兜底。冲突明确拒绝，不切换到另一个本地用户，不在失败事务里重试。
- 解绑和登录元数据更新共同锁定绑定行，保留已完成登录的时间及撤销历史。
  禁用提供商可以解绑，但不能创建绑定或更新成功登录信息。
- 控制器返回 `OIDC_BINDING_*` 诊断码与 `external-idp.binding.*` 翻译键；提供中英文资源，
  不把提交的 subject、邮箱或数据库异常作为消息参数。OAuth 登录错误保持原有协议码。
- 真实 PostgreSQL 测试覆盖共库/分库、外部 Primary 干扰、同一绑定并发幂等、subject/用户
  争抢、登录与解绑并发、提供商删除竞争、事务回滚、历史升级与重新绑定。浏览器身份核对
  使用单元替身，不等于与真实第三方 IdP 的完整回调验收。
