# 应用表单与审批链路可靠性验收

实施及验证日期：2026-10-23 至 2026-10-24。范围：平台生成的业务列表、表单新增/编辑、提交审批、待办/已办、审批历史；单体与微服务共用实现。

## 规则与修复

- **保存草稿与提交分开**：草稿允许暂缺提交必填项，已填写值的类型、长度、格式等约束仍生效；仅创建时可写的必填项不能拖到后续填写。提交，以及允许编辑的已提交记录，采用完整校验。界面明确说明草稿语义。
- 表单校验补充空白文本、空 JSON 集合、明细字段以及“编辑已有草稿时新加的仅创建可写明细字段”；错误显示在对应字段路径，并聚焦滚动到校验汇总。校验失败时展开包含错误的页签。只读提交的错误提示紧邻提交操作，避免长表单底部点击后看不到顶部错误。
- 已有业务记录的“提交审批”为只读确认，业务值发送空补丁，保留记录版本检查。事项标题、抄送人等流程信息仍可填写。直接发起新申请与驳回后修订保持独立语义。
- 单一可用流程自动选中；无可用流程、准备失败、表单/附件未就绪、提交状态查询失败均有明确反馈。受理后继续查询状态，区分受理和流程真正启动；不将网络不确定性变成第二次新提交。
- 审批历史按选中的业务记录查询，数据库分页与计数同时受租户、页面和记录约束。读取历史前复用实际记录读取服务校验数据范围。
- 有记录读取权限者可以查看该记录的不可变历史快照，并重新应用当前字段权限；不能因此重试他人的申请或重新申请。历史列表的流程进度入口保守地限于发起人；审批参与者仍通过自己的待办/已办访问流程详情。
- 已办操作明确为“查看”，打开业务只读快照；审批时业务数据只读，办理意见独立填写。审批完成后刷新待办、已办、事项和进度缓存。
- 审批变量编辑器、业务快照、公共表单和 Markdown 代码按需加载失败时，保留所属页面并提供局部重试；共享组件只缓存加载成功的代码，不自动重试业务写入。
- 未修改物理业务表结构、历史快照或已有业务数据。提交完整性和审批权限仍由服务端强制执行。

## 环境验收

- 单体入口 `https://single.simplepoint.online:8000` 和微服务入口 `https://home.simplepoint.online:8000` 已更新；10 个应用容器的运行镜像 ID 与验证清单一致，健康检查通过。沿用现有数据库及基础设施。
- 两个入口各核对 348 个宿主 JS/CSS 文件、6 个远程模块的清单/入口及合计 381 个声明资源，内容与发行包一致。生产中不开放的开发用 `mockServiceWorker.js` 不属于线上资源检查范围。升级前的带哈希静态资源已保留供旧页面使用。
- 两个入口分别执行 6 个流程实例：会议室行政审批、带两条明细的日报确认、普通报销、大额报销分级审批、驳回及修订后重提。合计 12 个实例：10 个完成、2 个按预期驳回。每个入口 12 项业务场景检查通过，包括时间先后、明细数量及精确合计、禁止篡改分支金额、附件必填、伪造文件引用、财务实际下载附件并核对摘要、越权审批和重复命令幂等性。
- 真实 Chrome 鼠标操作覆盖编辑保存、自动选定单一流程、只读提交且业务值为空补丁、审批历史、认领、办理、已办查看；新增浏览器流程实例为单体 `15001`、微服务 `17501`。已有记录提交以及待办/已办的业务字段均不可编辑。
- 两个入口均主动阻断一次审批表单 JS 下载：错误局限在加载组件内，待办列表保留；恢复网络并点击重试后，成功查看表单、完成审批，再从已办查看只读快照。测试工具先解除网络拦截再点击重试，避免拦截工具自身挂起恢复请求。
- 缺少“申请人姓名”的草稿在只读提交处明确提示缺失字段，提示会自动进入可见区域；服务端直接调用也拒绝提交，记录仍为草稿且审批历史计数为零。该负例草稿已清理。
- 审批记录快照在两个入口均可打开；等待抽屉动画结束后，各连续 3 次真实鼠标打开及只读断言通过，重复检查未出现传输错误。记录读取权限不扩展为流程操作权限：非本人重试被拒绝，跨记录读取快照返回 404，无业务页面权限返回 403；计数与分页也按记录隔离。

验证中曾捕获浏览器瞬时 `net::ERR_FAILED`。对应资源已通过逐文件校验；不能将该传输错误断言为资源缺失或业务审批失败。本次补齐局部失败反馈和显式重试，并完成故障注入后的实际审批；远程页面加载失败继续使用宿主已有的重新加载入口。验证覆盖上述场景，不代表穷尽全部自定义表单组合或外部网络故障。
