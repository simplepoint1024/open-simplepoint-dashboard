# 租户资源目录与套餐权益实施计划

更新日期：2026-10-23。状态：实施中。目标依据：本轮用户确认的租户独立资源目录、四类来源、套餐激活后计时及重叠资源时长叠加设计。

## 1. 已确认的交付边界

1. 平台空间读取平台资源相关表；组织和个人租户的资源、导航、角色授权、按钮、数据/字段权限最终只读取所属租户侧资源及权益。删除 PLATFORM/CUSTOM 双读取模式；不能仅改变页面入口。
2. 租户创建时，将当时有权获得的基础资源初始化到租户目录；完成基础资源与负责人权限准备后才允许空间进入可用状态。不得将 publicAccess（免显式授权）直接当作“所有租户可领取”的定义。
3. 平台来源资源保留平台 ID、稳定编码；租户主键/关联/缓存以 tenantId + resourceId 或 tenantId + resourceCode 隔离。平台表和租户表保持分离。
4. 来源统一为 PLATFORM（平台）、TENANT（自定义，保留既有编码）、APP（应用平台）、REPORT（报表平台）；取消 MANAGED 展示来源，保留管理方、业务键及既有业务生命周期。新增来源由统一枚举提供标签/筛选元数据；新业务管理行为复用受信注册契约。
5. 应用平台和报表平台的业务资源注册在租户下。手工资源和引擎生成资源按管理归属返回不同操作能力，不能因同为租户资源而允许绕过引擎删除/上下线。
6. 租户负责人使用“我的套餐”激活已分配的套餐实例；资源管理同样按当前租户负责人管理边界实施。页面可见性、schema、读取、写入均在服务端校验当前负责人；普通租户管理员不能仅凭页面授权获得此能力。
7. 多个套餐可同时激活。待激活实例不计时、不授权。同一实例内重复资源去重，跨实例时长叠加；并发/重试不得重复发放。
8. 有限时长按精确 UTC 时刻计算：newExpiresAt = max(now, oldExpiresAt) + durationDays × 24h。每个资源分别计算；同一套餐各资源最终到期时间可能不同。无期限权益显式表达，不用最大日期伪造。配额不使用该叠加算法。
9. 资源同步不增加版本字段、来源版本、目录修订号、历史版本或回退功能，也不增加“防止旧数据覆盖新数据”的校验。每次执行以平台当前定义为准，允许覆盖租户镜像中的原平台定义，以承接平台新增和变更的公共功能。保留创建时间、实际更新时间、最近同步时间，日期不参与新旧比较或拒绝更新。已有授权缓存失效计数、业务发布/正式下线协议不属于资源同步版本，不在此项中删除。
10. “检查更新”读取平台当前定义：添加新开放且符合当前租户条件的公共资源、更新已获资源定义；平台安全/执行字段受来源控制，允许的租户展示覆盖保留并支持恢复默认。普通检查不修改其他来源，不重复发放时长，不自动授权普通角色，不因一次查询缺失直接删除资源。
11. 正式撤销/安全停用通过既有可靠事件/领域边界同步到租户；菜单隐藏、本地停用、权益到期、正式下线分别表达。自然到期阻断使用并保留角色配置与数据；续期恢复的仅是仍未撤销的授权。正式下线撤销授权，再上线不得自动恢复。
12. 资源页镜像平台资源管理，复用 SimpleTable、服务端 schema/actions、标准抽屉、SForm、EntitySelect、TableActions、共享操作锁和时间格式化。共用契约与显示组件，避免复制一套 CRUD 控制器。

## 2. 当前源码基线与缺口

- 已有独立 TenantResource 表和复合主键；平台来源已保留平台 ID。
- 当前租户资源页面仅在 CUSTOM 模式可用；角色/上下文/路由仍存在平台/自定义分支及平台套餐实时查询。
- TenantResourceOrigin 只有 PLATFORM/MANAGED/TENANT，前端只呈现平台/自建；托管行显示不可执行的编辑/删除操作。
- 套餐定义有 durationDays，但 TenantPackageRelevance 只有 tenantId/packageCode，没有激活实例、起止时间、发放明细。
- 当前资源 schema 只提供查询能力、buttons 为空；页面手写表单、CRUD 和操作条件。
- 目录仅记录 updatedAt，localModified 是整行标志；需拆开平台控制字段与可覆盖展示字段。
- 现有工作树包含大量此前任务的未提交修改。本任务只修改相关文件，禁止 reset、整体覆盖或批量提交无关内容。

## 3. 模型与责任

### 3.1 租户资源

复用现有 TenantResource，保留平台引用、托管业务键与稳定身份。来源通过唯一来源契约解析，不能在 API、查询 CASE、前端各维护一份互不对应的分支。补齐创建/同步时间、有效状态及原因、允许操作、平台镜像所需权限元数据和展示覆盖。来源为平台不等于公开访问。

目录与权益分离：资源存在不代表已授权；租户权益、资源生命周期、角色授权及数据/字段策略共同决定当前访问。结构祖先按子资源补齐且不自动获得执行权限。

来源定义如下，列表标签、筛选选项和接口取值从同一来源枚举派生：

| 枚举值 | 显示名称 | 资源归属与更新入口 |
| --- | --- | --- |
| PLATFORM | 平台 | 平台定义同步到租户，租户记录保留平台资源 ID |
| TENANT | 自定义 | 租户负责人在租户资源管理中创建和维护 |
| APP | 应用平台 | 应用平台为所属租户注册，业务定义及上下线由应用平台维护 |
| REPORT | 报表平台 | 报表平台为所属租户注册，业务定义及上下线由报表平台维护 |

后续仅增加来源分类时，扩展统一枚举及其标签即可，接口、列表标签和筛选选项自动沿用该元数据，不新增来源专属资源表或列表控制器，也不要求各页面手工追加判断。来源标记本身不授予权限；新来源有业务注册行为时，接入现有受信注册契约，来源枚举不承担引擎业务实现。套餐是平台资源的权益取得途径，不另设“套餐”来源。

### 3.2 套餐实例

将平台套餐定义与租户持有实例分开。每个分配实例有独立 ID、租户、套餐标识、可解释的资源内容/时长快照、分配/激活时间、状态及撤销记录。同一套餐可存在多个续费实例。快照仅记录本次发放依据，不引入资源版本或版本比较。

激活采用数据库事务与实例/租户锁：检查负责人 → 校验实例归属与状态 → 去重资源 → 更新租户资源定义 → 逐资源发放 → 标记已激活 → 失效授权缓存。实例 ID + 资源 ID 是唯一发放键；已激活重试返回原结果，不重置起算时间。

### 3.3 权益明细与汇总

权益明细保留来源实例、资源、发放时长、激活时间、分配的有效区间、撤销/历史状态。汇总用于当前资源的有效期读取；不能只存一个无法解释来源的 expiresAt。无期限权益与有限权益明确区分，撤销必须能从仍有效的明细重新计算。

套餐撤销采用以下消费规则：同一资源按激活时间、发放记录 ID 稳定排序，先激活的时长先消费。撤销只移除该实例尚未消费的部分，保留已消费的历史和其他实例剩余时长，不将其他实例的消费时间倒算到过去。无限期权益阻挡其后排队的有限时长消费；撤销无限期权益后，后续仍有效的剩余时长继续使用。已经完全消费的实例被撤销，不扣减之后续费产生的权益。全部权益耗尽时移除当前汇总，保留资源和历史发放记录。

撤销属于平台管理员管理动作，与负责人激活入口分离；租户管理员标记不能替代平台作用域。撤销、汇总重算、执行人记录和授权失效处于同一租户锁及事务中，与分配/激活串行；重复撤销返回原回执，不再次扣减。套餐撤销本身不删除角色配置或业务数据，也不替代正式资源下线协议。

套餐内容在分配时保存资源 ID、编码和名称，供待激活明细展示。该记录是购买内容依据，不是可同步、比较或回退的资源版本；历史 ID-only 记录保留未知名称，不用当前平台名称伪造历史。明细分别展示本次激活原始到期时间与资源当前叠加到期时间，当前时长权益不代表已获得角色授权或资源处于上线状态。

到期检查在授权读取/写入及缓存使用边界执行。缓存截止时间不能越过最近的资源权益到期时刻；到期任务只负责通知/整理，不作为唯一安全机制。负责人也不能绕过业务权益到期。我的套餐、必要的空间管理/退出入口属于基础管理资源。

### 3.4 初始化、同步与事件

初始化与手动更新读取同一平台定义适配器，但运行期租户权限不能回退到平台资源。公共基础资格由明确的平台发行/租户初始化政策提供，不猜测 publicAccess。同步通过租户锁串行，在事务内读取当前定义并更新；不引入资源同步版本或回退。

当前基础发行策略复用内置 CORE（核心工作台）和 STORAGE（对象存储）应用的明确资源成员，组织/个人分别按资源适用范围过滤；应用本身必须存在且启用。该选择复用既有个人基础套餐策略，不通过 publicAccess 推导免费资格，不将 AI/APP/WORKFLOW 应用自动作为基础权益发放。发行策略集中在身份模块的适配器，初始化和手动更新共享该定义。

目录准备状态与资源定义分开，使用 INITIALIZATION_REQUIRED / ADOPTION_REQUIRED / READY。V14 将已有未删除租户标记为待显式接管，不补发权益、不修改目录或历史授权。普通新租户在创建事务中完成资源准备后写入 READY；失败回滚租户及成员关系。启动种子组织先于平台资源声明注册创建，仅此受信启动路径在同一创建事务写入 INITIALIZATION_REQUIRED；随后 common 权威资源注册在同一身份事务中维护基础应用成员并完成这些组织的目录初始化。初始化失败时注册失败并回滚，重试继续待初始化项，不更新 READY 目录，不接管 ADOPTION_REQUIRED 历史。V16 仅扩展状态约束，不改变既有状态和日期。该状态不是资源版本，也不用于更新时的新旧比较。

“检查更新”的具体处理为：

1. 执行时读取平台当前开放且符合租户资格的资源定义；新增资源按平台 ID 导入，已有平台来源资源按当前定义更新。
2. 不提交或比较资源版本、来源版本、预览版本；不以更新时间判断新旧并拒绝覆盖，也不保存可回退的资源历史快照。若提供预览，实际执行时重新读取平台当前定义。
3. 创建时间保持不变；定义发生变化时更新实际更新时间；完成同步时记录最近同步时间。日期仅用于展示和审计，不作为版本校验依据。
4. 保留允许的租户展示覆盖，平台控制的功能和权限元数据更新为当前定义；APP、REPORT、TENANT 来源不由平台公共资源检查更新覆盖。恢复平台默认仅重置展示覆盖，继续保留手动停用和正式下线状态。
5. 同步事务与串行执行仅保证一次更新完整提交，不承担资源版本比较。更新不增加套餐时长、不恢复已撤销角色授权、不改变其他来源的业务归属。

保留已有受信模块注册、安全校验及正式上下线事件，平台撤销事件更新租户状态并使缓存失效。需业务确认的跨服务操作等待持久回执；报表来源在本任务接入通用契约和验证夹具，不将“建设整个报表平台”扩大为本任务范围。

### 3.5 历史权益显式接管

旧租户的套餐关系没有历史激活日期，且旧授权查询没有使用套餐时长判断过期。因此接管保留既有持续权益，采用可撤销的无期限历史发放明细；不把配置中的 30 天等时长从接管日重新算作购买权益，也不猜测过去的消费时间。新的购买实例仍遵循分配后待激活、激活后计时的规则。

取得方式与资源来源分开：ASSIGNED 为正常分配，LEGACY_PACKAGE 为历史套餐，LEGACY_PUBLIC 为旧公共资源资格，LEGACY_ROLE 为旧 PLATFORM 模式中未被前两者覆盖的有效角色资源资格，LEGACY_HOST 为已有有效应用/报表页面实际引用、但旧版应用成员遗漏的私有非授权宿主资格。这些是套餐/权益取得方式，不增加第五种资源来源。公共资源、角色资源和宿主接管不显示成购买的套餐；界面明确展示接管日期，原始激活日期保持未知。

接管仅由平台管理员显式执行，组织与个人租户均以同一租户数据库锁串行。预览不写入；执行重新读取旧关系、当前定义和当前基础发行策略，不比较预览版本。目录、历史实例、发放明细、权益汇总、READY 状态、执行人和授权失效处于同一事务；已成功接管的重试返回原回执，不重新导入或发放。

旧关系的软删除标记必须逐项过滤。套餐或应用停止销售不等于撤销已经存在的旧许可；资源的停用、空间适用范围和正式下线仍约束实际使用。保留旧 CUSTOM 目录的展示覆盖、停用和刻意省略的付费页面，不将省略页面导入后自动启用；结构父级可补齐。已撤销角色授权不恢复，跨租户归属不一致的历史授权拒绝接管并要求先修复。

历史来源使用正常撤销账本：撤销一个来源后，其他来源保留；排在无期限权益之后的有限续期时长不被误消费。公共更新不重复接管历史资格。接管回执中的资源数和实例数表示本次接管事实，后续撤销不会改写它们。

正式升级必须先完成身份模块迁移及显式业务接管，再开放新登录/租户授权路径。已提供身份域管理 HTTP 入口和不依赖登录的离线安装入口。离线入口与 HTTP 共用事务存储；HTTP 保留平台管理员校验，离线端口不参与运行期组件扫描或 RPC 导出，并拒绝请求/认证上下文。正式环境的全量授权差异和内置组织准备状态仍需验收；不能依赖旧用户登录时自动接管。新个人空间准备服务会拒绝 ADOPTION_REQUIRED，因此缺少这一步的发行包不可直接部署。

管理入口由 identity-http 模块挂载，保持共用领域实现：

- `GET /platform/tenants/{tenantId}/resource-adoption/preview`：平台管理员查看当前待接管事实，不写入。
- `POST /platform/tenants/{tenantId}/resource-adoption`：平台管理员执行接管，不提交资源列表、版本或历史时间；返回持久接管回执。
- 实际公共路径使用模块 HTTP 挂载前缀（当前为 `/common`），不能在控制器另写宿主前缀。方法要求认证，领域再次校验明确的 PLATFORM 作用域及平台管理员身份；组织管理员、个人空间或缺失上下文均不可执行。
- 每个租户单独事务提交，失败后可按同一租户重试；整批执行的租户清单、授权差异核对、未完成项和重试结果应保存为升级证据。此入口不等于已经完成全量升级，不开放匿名迁移或伪造管理员上下文的入口。

## 5. 迁移方案

1. 使用 identity 拥有的 @ModuleMigrations/manifest 新增不可变 SQL；不修改已发布迁移，不使用 ORM 自动改生产表。
2. 保留租户资源 ID、编码、角色授权、业务键、已正式下线状态。来源为 app 的历史 MANAGED 记录映射 APP；未知管理方需明确映射，不能默认为自定义并开放删除。
3. 旧租户套餐关系没有激活时间，禁止用创建时间猜测已消费时长。将已生效历史许可显式接管为保留现有权益的历史来源，展示“历史接管”；新增套餐实例才应用待激活规则。迁移前后授权差异必须可核对，不自动复活 revoked 授权。
4. 旧 PLATFORM 租户初始化现有可用目录；旧 CUSTOM 租户保留展示覆盖。移除读取分支前补齐全量目录与权限描述。组织与个人空间均验证，新用户创建路径同时接入。
5. 先在隔离 PostgreSQL 副本验证迁移/数据守恒，再构建含前端发行包。涉及正式环境更新时按平台协调升级要求执行，禁止旧未迁移写入者并行写新模型。
