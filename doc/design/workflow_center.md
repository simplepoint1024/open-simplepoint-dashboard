# 流程中心设计与交付基线

## 目标与边界

流程中心是与 Common、DNA、AI、App 平级的独立服务，服务名为 `workflow`，网关前缀为
`/workflow`。Flowable 只作为服务内部的 BPMN 2.0 执行引擎，浏览器和其他业务服务不能直接访问
Flowable 数据表或原生 REST API；所有访问都经过平台认证、租户隔离、资源权限和流程中心领域接口。

前端 `simplepoint-workflow` 是独立微前端。BPMN 建模器与流程状态图不属于业务页面私有实现，分别
封装为 `WorkflowDesigner` 与 `ProcessStatusDiagram` 共享组件，供流程中心和后续应用工作台复用。

## 兼容性决定

- 平台基线：Java 21、Spring Boot 4、Spring Framework 7、Jackson 3（兼容 Jackson 2）。
- 流程引擎：Flowable 8.0.0。Flowable 7 的官方基线是 Spring Boot 3；Flowable 8 才支持
  Spring Boot 4，不能通过排除依赖强行组合 Flowable 7 与本平台。
- 建模器：`bpmn-js`。流程 XML 使用 BPMN 2.0 与 Flowable 命名空间，服务端在发布前再次解析、
  校验和实施安全约束，不能信任浏览器校验。

## 领域模型与版本规则

`simpoint_workflow_definitions` 保存稳定流程身份和当前草稿；
`simpoint_workflow_definition_versions` 保存每次发布的不可变快照。流程 key 在租户内唯一，已发布
版本只增不改，版本记录同时保存 XML、SHA-256、发布说明、Flowable deployment id 和 process
definition id。相同草稿重复发布保持幂等，不制造伪版本。

发布事务必须完成：

1. 锁定流程定义并校验预期草稿修订号；
2. 解析 BPMN，确认唯一可执行流程、稳定 key 和受支持节点；
3. 拒绝脚本、任意 Java class/delegate expression、外部 URL 等不受控执行入口；
4. 以当前租户部署到 Flowable；
5. 写入不可变平台版本并更新最新版本；
6. 任一步失败时不得把版本标记为已发布。

运行中的实例始终绑定启动时的版本。发布新版本只影响新的实例。历史版本可查看、比较和按显式
版本启动；“回滚”通过从历史版本复制出新草稿并再次发布完成，不修改旧版本。

## 租户、身份和授权

- 所有定义、版本、实例、任务、抄送和通知均以授权上下文中的 `X-Tenant-Id` 为强制边界。
- Flowable deployment/process/task 的 tenant id 必须与平台 tenant id 一致。
- 用户任务的 assignee 使用平台 user id；candidate group 使用平台授权上下文的 role authority。
- 抄送用户通过 `TenantService.resolveActiveMemberIds` 做至多 50 个指定 ID 的租户成员交集校验；
  该接口不返回完整成员目录，普通调用者仍需属于目标租户，服务间调用则要求
  `SCOPE_service-router.invoke`。
- 类型化人员/角色变量及引擎最终解析出的任务办理范围都在同一事务内校验有效成员/角色。
  `resolveActiveRoleAuthorities` 校验本租户未删除角色的 authority，不把角色记录 ID 当作候选组；
  不存在、已删除或其他租户的办理范围不得留下实例、任务、平台投影或通知 outbox。
- 每个控制器同时校验页面/动作资源。管理员能力不绕过租户边界。
- BPMN XML、变量和评论设置尺寸、类型和字符约束；接口不返回引擎内部异常或数据库信息。

## 待办、事项和消息融合

流程中心提供统一工作事项视图：待处理、已处理、我发起、抄送我的。待办直接来自 Flowable 当前
任务，已处理来自历史任务，我发起来自历史实例，抄送使用流程中心持久化记录；不复制一份可能与
引擎漂移的“待办主表”。

任务到达和流程结束生成事务性 outbox 事件。异步分发器通过平台服务路由调用 Common
的定向通知接口。带租户的流程消息写入 `PersonalInboxGateway` 的“我的消息”，与个人首页和铃铛
共用未读状态；不再额外创建一份系统通知。普通公告仍使用原系统通知通道。现有服务路由负责内部
身份验证，个人投递网关保持进程内接口，不直接暴露 HTTP/RPC。共享令牌缺失或不匹配时禁止退回
普通用户认证。个人通道未就绪时必须重试，不能降级成不受租户隔离的全局消息。

失败事件按退避策略重试；幂等键转换为固定长度 SHA-256，接收人／工作空间／来源共同限定唯一性。
业务事务不因 Common 暂时不可用而丢失。消息使用 `/my/todos?task=…&instance=…`、
`/my/items?instance=…`，抄送链接附带 `view=copied`，所有链接重新执行服务器可见性校验。
明确指派的任务只通知实际办理人；未指派任务通知候选用户及当前有效候选角色成员。角色解析是受限的
内部服务接口，每批至多 50 个角色、200 个接收人，使用游标分页并批量去重，不拉取整个成员目录。
消息只代表产生时的提醒，不授予办理权限；之后的成员／角色变更仍以实时待办权限为准。

首页工作流摘要复用同一待办／事项查询边界，每张卡片最多五条预览，总数由数据库计算。
事项显示本人仍在进行的实例，待办显示本人当前可办理任务；没有相应权限时仅返回能力状态，不查出
受限数据。个人消息目前有按工作空间隔离的轮询，尚不宣称流程消息已实现实时 SSE 推送。

## 前端组件契约

### `WorkflowDesigner`

- 导入/导出 BPMN XML、撤销/重做、缩放/适配、脏状态和服务端错误定位；
- 支持开始/结束事件、用户任务、排他/并行网关、顺序流和子流程等平台允许的 BPMN 元素；
- 属性面板维护流程名称、元素名称、用户/候选用户/候选角色、到期时间、优先级、条件表达式和说明；
- 输出前运行结构校验，发布仍以服务端校验为准；
- 组件不发业务请求，不包含页面权限和保存按钮。

属性选择复用有界、按租户/角色上下文隔离的 `EntitySelect`/`TenantDirectorySelect`。
条件配置复用平台条件编辑器，人员和角色比较值仍使用目录选择器；普通/高级模式切换不重写原表达式。
值编辑器的固定值/流程变量/高级表达式也采用同一契约：切换仅修改本地展示模式，不调用模型写入，
不默认选择首个变量，也不恢复先前缓存的固定值。固定值的高级形式与常量表达式的普通形式仅作预览；
只有用户实际选值或编辑时才提交新值。外围空白的变量表达式保留原文，不被包装成字符串常量；
不能普通表达的复杂、缺失或不支持的语法继续保留高级编辑器，并提供转换提示。
数值常量预览保留原词法文本（大整数、精确小数、指数与负零），不先通过 JS Number 改写。
用户/角色选择器的数字常量身份预览则使用 Flowable 的实际 `Number.toString` 结果，例如
`${1e2}` 查找身份 `100.0`，而带引号的 `${"1e2"}` 仍查找身份 `1e2`。
定义页通过作用域隔离的查询缓存注入只读解析器；画布和通用值编辑器不绑定业务 API。
相同常量跨属性及重开设计复用成功查询，迟到结果不能覆盖新值；预览失败保留原表达式并允许
明确选择替代身份或重试，不把数字源码当作目录 ID，也不阻止保存未经改写的原表达式。
`GET /definitions/literal-preview` 仅允许流程定义阅读者或管理员调用，只接受 500 字符内的
单个数字常量，使用无变量、无业务 Bean 的上下文求值，并以 JSON 字符串字段返回身份文本；
不开放通用表达式求值，不读取或修改目录、定义或流程实例。
优先级使用独立注入的字段解析器及 `GET /definitions/priority-preview`，与身份 `toString` 规则分开：
数字按真实 `Number.intValue()` 截断、溢出或饱和，字符串按 `Integer.valueOf()` 解析（含引擎认可的
Unicode 数字）；布尔及非法整数文本明确拒绝，`null` 保留引擎默认值。接口仅接受有界固定值及
单个字符串/数字/布尔/null 常量，不求值变量、方法或复合表达式。预览失败不使用 JS 舍入兜底；
迟到无效结果不能修改新值有效性，成功查询可复用，切换及实际保存均保留原文直到明确编辑。
布尔常量输入同步报告字段无效，保存校验器也按同一原生规则拒绝已知非法常量，动态表达式仍只
编译、不求值。共用的优先级夹具同时用于真实 Flowable 任务、后端预览/保存验证和实际画布回归。
到期时间的独立字段检查只拒绝确切的布尔/数值常量结果，不将毫秒数猜成日期；引擎要求日期类型或
日期/时长文本。前端输入同步公布无效状态，服务端保存同样拒绝，避免同一事件中输入并保存漏过。
日期/时长字符串、变量和 `null` 不由该类型检查求值或改写；共用夹具由真实引擎任务、保存校验和
画布编辑/序列化回归验证。已有日历格式不能无损编辑时继续保留原文，不把类型检查冒充日历求值。
普通绝对日期控件只展示具有明确时区偏移、完整时间且真实存在的日历日期；没有偏移的旧值不按
浏览器时区猜测。引擎会把 `2026-02-30` 收敛到二月末，浏览器库却可能滚动到三月，不能照此显示。
此类已被引擎接受的旧写法仍保留原文，显示明确的固定值替换提示，不禁存、不擅自改写日期。
条件表达式的数值字面量也保留词法文本及字面量类型，普通配置继续使用平台的精确数值输入控件。
实际编辑数值时按声明类型输出数值而非加引号的字符串；编辑相邻条件不会舍入已有数值。
带引号的数值文本与真正的数值字面量不混淆，类型不兼容的比较仍保留高级模式。
普通条件按全局节点数和深度限制检查，变量索引按声明缓存，不逐节点反复遍历声明数组。
字符串使用真实 Flowable/JUEL 规则而非 JSON 字符串转义，单、双引号与合法 XML 字符均可往返；
换行、回车和制表符作为实际字符保留，普通字符串条件可选用共享多行输入，其他查询输入不变。
高级表达式编辑器保留回车字符，编辑相邻子句不规范化字符串内容；原生 BPMN 导出后按 XML
语境保护正文回车与属性空白，存在这些字符时才线性处理，不修改模型或第三方序列化器。
真正的反射访问仍被阻止，反射样式的纯文本不误判为调用；前后端均拒绝不支持的字符串转义。
草稿校验器用真实语言工厂做有界语法编译，不求值动态表达式、不绑定业务变量或应用 Bean；
只有优先级的严格常量白名单走上述原生字段转换。
明确选择的固定标识若包含模板标记，将编码为字符串常量，避免真实角色权限值被当作变量执行；
只有明确选值会进行此编码，视图切换仍不写配置。
角色目录仍显示真实角色，不修改权限记录；包含逗号、首尾 ASCII 空白、控制字符或超过长度限制的
权限值不可直接选择，并给出原因。CSV 无法表示单个含逗号的权限值，不能把它静默拆成其他候选组。
选择器与变量表单共用有界的角色值检查；共享夹具对照后端 `String.trim`/`Character.isBlank` 规则，
避免 JS `trim` 把后端认可的 Unicode 权限值误拒绝。正常独立角色多选及模板标记仍保留原生行为。
属性编辑不重建按用途过滤的声明数组及值编辑器的声明索引；声明或翻译变化时才更新。
流程定义、任务和实例的首屏同步资源也纳入现有微前端预算，按与 Common 同样的 8 请求/90 KiB gzip
页面及 512 KiB 入口上限检查；BPMN 画布、语言编辑器及表单运行时按需加载。
真实设计器回归通过保存请求解析五项任务属性，覆盖模式往返、用户/角色选择、常量预览、
选值后不恢复旧值、复杂表达式保留，以及同浏览器任务内输入非法表达式后保存被阻止。
未完成的条件草稿按节点保留并阻止保存，输入回调先同步公布草稿与有效性再修改模型，
同一浏览器任务内输入后立即保存也不能绕过校验。高级值的实际编辑按表达式校验，
不会把缺少包装的错误文本当作固定值保存；既有固定值的高级展示仍仅为预览。
普通/高级模式切换在同一事件中优先判断当前输入，不读取尚未确认的旧属性。短暂输入视图在父级
确认、受控值或所有者回调变化后失效；原生撤销不能恢复已确认的输入缓存。模式切换仍只改变视图，
不生成模型命令、不改写配置；同事件的简单/复杂输入、原生撤销与真正保存均由画布回归验证。
画布通过 bpmn-js 的 provider 扩展默认创建 `UserTask`，
不通过隐藏 CSS 提供服务器禁止执行的任务类型。相对到期时间支持 ISO duration 的日/时/分/秒配置；
不能无损转换的已有值保留原文，不猜测或清空。

### 表单引擎扩展点

`WorkflowFormContract` 与发布 XML 一起成为不可变版本快照，包含变量类型、阶段、默认值和
`provider / formId / version / variableMappings` 绑定。运行时返回实例锁定版本的字段和值，
不拿当前草稿或最新发布版本替换正在运行的表单。

前端应用显式调用 `registerWorkflowFormAdapter`，实现设计绑定、发起表单及任务表单渲染。
注册表通过版本化 `Symbol.for` 在同一浏览器 realm 中共享，订阅通知使已挂载消费者感知注册/卸载；
不同微前端各自打包共享库时也不会产生互不可见的注册表。后端通过显式注入的
`WorkflowFormProvider` 校验绑定及提交映射。保存的 provider 名称不能触发任意模块或 URL 加载。
绑定未接入的提供方时明确报错并阻止提交，不静默退回其他表单绕过验证。

发起/办理统一使用类型化 `SForm`，不再提供“表单填写／高级 JSON”切换入口；表单引擎适配器可提供
自定义字段组件，但不能改变服务器的权限和版本边界。变量数量、大小、深度、保留名称和阶段校验保留。
没有声明字段却带有旧变量的数据明确阻止提交并提示完善表单配置，不静默提交用户看不到的数据。
运行时变量编辑器的 `getValues(expectedForm)` 在提交边界同步读取最新草稿，校验表单所有者、
当前解析错误、提供方有效性、阶段字段及统一的大小/深度/类型约束，并返回独立数据快照。
普通控件和提供方回调先同步公布草稿；发起和办理提交不以滞后的 React 有效性状态或
旧父组件值作为最终依据。无效输入后同一事件立即提交不会请求服务器，合法即时编辑提交新值；
旧提供方的迟到回调不能为替换后的适配器提交值或授予有效状态。

### `ProcessStatusDiagram`

- 只读导入 BPMN XML；按 activity id 标记未到达、已完成、当前、取消/异常状态；
- 支持缩放、适配、图例、当前节点聚焦和无障碍文本摘要；
- 组件不自行查询实例，便于在任务抽屉、实例详情和业务详情中复用。

## 页面与资源

流程中心菜单只保留“流程定义”和管理人员的“运行管理”。个人审批统一进入“我的待办”的待办／已办，
发起、抄送、撤回、取消与关联重提统一进入“我的事项”；不再展示独立任务中心。
原任务、个人实例资源代码与动作父级保留为隐藏兼容资源，避免改变已有授权；全部实例权限代码升级为
“运行管理”页面。创建、保存、发布、复制版本、启动、认领、办理和取消等仍由服务器最终授权。
列表使用平台 `DataTable`/`SimpleTable` 和 `TableActions`，结构化表单使用 `SForm`；只有 BPMN 画布、
属性编辑器和确认对话框使用专用交互。

## 运维与完成门禁

- Flowable 使用同一受管 PostgreSQL 数据源；首次引导时显式开启 schema bootstrap，完成后关闭自动
  upgrade，后续版本在维护窗口执行受控迁移，不使用临时内存库。
- 服务具有 Consul 注册、OAuth2 client credentials、健康检查、指标、容器镜像、网关稳定路由和
  前端微模块清单。
- Workflow 对 `saas.tenant` 和 `notification.delivery` 显式路由到 Common。平台内存在多个实现相同
  远程契约的进程时不得依赖 Consul 服务扫描顺序，以免请求命中非权威 Provider。
- 单元测试覆盖版本幂等/并发、租户越权、BPMN 安全校验、任务权限和通知 outbox；PostgreSQL 集成
  测试覆盖 Flowable 建表、部署、启动、办理和历史查询；浏览器回归覆盖设计保存/发布、待办办理及
  状态图。
- 部署完成必须验证容器健康、Consul passing、资源和 i18n 注册、真实数据库中的版本/实例/任务闭环，
  以及通过 HTTPS Host 加载微前端。仅通过编译或模拟接口不等于完成。

## 个人工作流统一入口实施计划（2026-10-11）

本节依据本轮用户需求，取代“任务中心独立承接审批”的旧入口设计。质量与完整度优先，
按下面的产品契约逐项实现并记录实际验收，不以隐藏菜单代替领域和数据迁移。

### 入口与业务边界

| 入口 | 内容与操作 |
| --- | --- |
| 我的待办 | 工作流待办／已办切换；认领、通过、驳回；统一表单、进度与办理记录 |

个人工作空间应有明确的组织切换提示，不能请求组织流程后只显示接口错误。

### 操作与历史契约

- 通过是一次任务的审批结果；仍有后续节点时，实例保持运行中，不能将节点通过等同于整条流程完成。
- 推荐驳回语义：结束本轮审批并保留意见与历史，发起人可修改后重新发起，关联原实例和实际版本。
  已向用户发出语义选项；若选择退回节点或原实例继续，则先调整状态与模型设计，再实施该部分。
- 撤回由发起人对未结束实例操作；取消由具备对应管理权限的人执行。两者保留不同结果与原因。
- 待办是当前用户实际可办理或认领的任务。已办包括本人的办理及撤回／取消操作、本人已分配任务的
  终止结果；历史中的操作结果与实例最终状态分别展示。候选角色的目录变化不应伪造本人曾经办理。
- 审批日志记录真实操作者、任务执行标识、动作、意见和时间；旧记录缺失的信息明确缺失，禁止补造。
- 以实例为事务并发边界，协调引擎、平台状态和 outbox；已处理任务、重复提交、认领竞争以及审批与
  撤回并发不能产生矛盾终态、重复动作或跨租户数据。

### 查询、身份与进度

- 列表通过同一平台查询契约开放表头检索、排序、高级条件和保存视图。服务器分页必须在数据库筛选、
  排序后执行，不能将本页本地筛选伪装成全量查询；计数、过滤和数据权限一致，排序增加唯一平局字段。
- 逐页登记标准列表及可查询字段。操作列、图形和不能合理比较的复合字段列为明确例外；隐藏／脱敏
  字段不借查询、排序或名字补全泄露。查询保持有界，不为统一 UI 加载全部目录或全量历史。
- 发起人、办理人及记录使用真实姓名；候选组展示真实角色名称。每页批量解析，已删除、已离职或不可见
  身份给出明确说明，内部 ID 不作为用户姓名回退。历史操作者与当前候选名单分开。
- 状态图按每次活动执行展示，区分通过、驳回、撤回、取消和当前待处理。循环／并行不能按相同 BPMN
  节点 ID 把过去执行误标为当前。点击节点读取真实审批人、候选范围、意见、结果和起止时间。
- 画布及可键盘操作的节点记录列表共用选中状态。重复导入、切换实例和迟到的详情响应不得串到新实例。

### 已落地的查询架构与验证边界

- 引擎仍是任务事实来源，不复制到旧的个人待办表。`WorkflowActionEntity` 与引擎变更同事务提交，
  对任务决定及实例终止分别建立唯一键；实例悲观锁协调认领、审批、撤回与取消。
- 按仓库既有只读投影模式，`WorkflowInboxReadModel` 合并引擎任务历史及没有对应任务的个人操作。
  筛选、排序、分页及总数均通过平台 `ProjectionQuery` 在数据库执行；用户和租户条件独立追加。
  个人操作不会因没有任务而丢失，同一操作不会额外重复为流程记录；未认领候选人不会被计为办理人。
- 查询适配器明确依赖当前共享数据库和固定的 Flowable 8 表结构；禁止写入引擎表。升级引擎或拆分
  数据库时必须替换／验证该适配器，不能把当前实现宣称为跨数据库方案。
- 同一身份投影用于显示、筛选和排序：优先显式 `User.name`，再兼容姓／中间名／名，缺失时显示邮箱。

### 后台推进与消息升级

- `WorkflowEngineSignalListener` 捕获真实任务创建／指派及流程结束事件，在引擎事务内追加持久化信号。
  既覆盖 HTTP 办理，也覆盖定时器／异步作业。候选身份链接完整后，在提交前按真实任务租户校验人员／角色；
  非法后台指派与信号一起回滚，不留下跨组织或不可办理的任务。
- 引擎回调不拿平台实例锁、不更新平台状态。独立消费者只处理已提交信号，每批最多 50 条、每条单独事务，
  先锁信号再锁实例，复用幂等通知键；失败回滚后在新事务记录退避重试，单条异常不阻塞其他实例。
  成功消费删除的是临时队列信号，不删除业务审计。自动完成取引擎结束时间，不伪造人工通过记录；
  已有驳回／撤回／取消结果不会被迟到事件改写。
- 安装前先备份并停止旧工作流投递。新服务的 `schema.sql` 增量创建审计、关联重提和引擎信号结构。
  在共享 PostgreSQL 中，以 `psql -X -v ON_ERROR_STOP=1 --single-transaction -f
  doc/deployment/sql/20261011-workflow-personal-messages.sql` 迁移旧消息。
  仅处理来源为 workflow、已发布且未过期、接收人与 SENT outbox 相同、实例与 outbox 租户相同的定向通知。
  原系统通知和回执不删除，迁移后旧通道标记 REVOKED；逐条映射与原版本保存在迁移台账。
- 个人消息保留原发布时间、准确已读时间和同一 SHA-256 幂等键。已有个人消息不覆盖内容、归档／删除状态；
  旧任务、完成与抄送消息补成具体详情链接。未知归属、未匹配、过期或已撤销消息不猜测迁移。
  `node scripts/node/verify-workflow-migration.mjs` 只连接固定 45439 端口的临时测试库，验证可重复执行、
  跨租户拒绝、回执归属、已有记录保护及整笔事务失败回滚。
- 新资源清单注册后，再以单笔事务执行 `doc/deployment/sql/20261011-workflow-personal-navigation.sql`。
  它检查上游清单版本，隐藏旧任务／个人实例菜单及别名，将旧全实例动作提升为独立运行管理页；
  保留资源 ID、代码、角色授权、自定义名称／路径及手工禁用状态，仅为实际变更租户递增授权版本。
  原行 JSONB 留在迁移台账，重复执行不重复变更或递增版本。禁止在旧清单仍在运行时提前执行。
- 回退前保持维护状态并使用本次部署前的整库备份／镜像与配置快照；开放业务写入后不得直接恢复旧库覆盖新数据，
  应先单独评估迁移台账及新增业务记录，优先前向修复。迁移脚本不删除手工待办、旧事项或历史审批。

### 关联重提与平台操作记录

- 驳回、撤回、取消后，由有发起权限的原发起人修改并创建新实例。新实例保存不可变
  `previous_instance_id`，唯一索引及原实例悲观锁保证同一轮至多产生一个后续实例；原结果和历史不变。
  新一轮再次结束后可继续建立下一轮，不允许重新利用已经产生后续实例的旧轮次。
- 重提沿用原已发布版本，而非静默迁移到最新版本。表单仅预填该版本发起阶段允许的业务变量，
  不返回引擎保留变量；重提时重新校验变量类型、目录成员、抄送及外部表单。原版本不可用时明确阻止。
- 进度详情可沿原事项／重新发起事项查看关联记录，每次切换仍由服务器重新校验实例可见性；
  非原发起人即使是管理员也不能代替本人重提。并发重提、版本篡改及启动失败回滚均有真实引擎测试。
- 操作时间线分页展示已记录的平台发起、认领、通过、驳回、撤回、取消和重提事件，操作者使用同一实名
  目录投影，最多 50 条一页、批量补全姓名及节点名称。节点执行历史与平台操作日志明确分开，
  不把引擎活动自动推断成人工审批；没有从发起时开始记录的旧事项显示历史覆盖提示，不补造记录。
