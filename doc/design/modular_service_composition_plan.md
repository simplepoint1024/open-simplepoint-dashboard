# 模块组合部署与单体聚合服务实施计划

日期：2026-10-20。状态：实施中，全部目标尚未完成。

## 1. 用户目标与完成边界

来源：用户明确要求确认缺口、形成文档并逐项补齐，最终在服务列表新增能够完整使用的单体聚合服务。

| 编号 | 强制要求 | 完成依据 |
| --- | --- | --- |
| U1 | 最大程度解耦，灵活可控 | 业务能力不依赖物理宿主名称；领域之间只依赖公开契约；拓扑变化不复制业务实现 |
| U2 | 配置自动化，开发者手动配置最小化 | 模块声明被自动发现；自动生成装配、路由和必要基础设施计划；只要求环境地址、凭据和必要策略 |
| U3 | 架构清晰，模块可自由组合 | 支持合法依赖闭包下的同进程、分离及混合部署；非法组合在启动/构建时给出明确原因 |
| U4 | 代码简洁、质量优先 | 公共机制集中实现、兼容现有微服务；契约、安全、失败恢复及真实部署验证通过 |
| U5 | 新增正式单体聚合服务并完整可用 | `simplepoint-services/simplepoint-service-standalone` 可构建、启动和部署；登录、前端、权限、DNA、表单、流程、审计及已提供的 AI/MCP 功能可用 |

单体版目标是一个平台 JVM 应用与统一浏览器入口。不得用同时启动原有多个 Java 服务的脚本替代。外部数据库、Redis、RabbitMQ、独立执行不可信工具的隔离设施仍按原职责存在；不把外部基础设施误称为单体缺陷，也不将原平台必要入口留给未声明的旧微服务。

单体版正式入口确定为 `https://single.simplepoint.online:8000/`，须单独启动并验证与微服务版功能等价。DNS 与独立 HTTPS 预留入口已就绪；实际服务接入须等待单体业务验收，详见[入口记录](../deployment/single_entry.md)。

已有数据迁移不得默认破坏当前环境。单体先使用隔离环境和可复现业务数据验证，再进行受控部署与回归。微服务版继续作为正式支持拓扑。

不将“所有组合”解释为允许破坏必需依赖、身份边界、数据库所有权或多实现选择规则。合法组合必须有确定、可解释的装配结果。

## 3. 架构决定

### 3.1 分离四类身份

- 模块身份：稳定的领域/能力拥有方，不因部署变化重命名。
- 契约身份：公开 API 名称和版本，继续以 `RemoteContract`/`RoutedService` 为权威。
- 宿主身份：一个可运行应用及其实例，决定进程、地址、健康和容量。
- 资源身份：页面、权限、数据/字段和前端 remote，沿用现有稳定身份。

事件生产者表示逻辑拥有方，基础设施验证当前宿主确实被授权承载该身份；不通过修改历史 producer 或放宽 broker ACL 兼容组合。

### 3.2 模块装配契约

模块声明仅描述不能可靠推导的信息：稳定模块 ID、版本、配置入口、所需模块/能力、逻辑 HTTP 命名空间、存储/任务/事件/前端贡献。公开接口能力直接从现有契约推导，不能再维护一套不一致字符串表。

宿主选择根模块，自动计算本地依赖闭包；允许外置的能力经服务发现解析。缺失必需能力、重复提供方、同名路由、资源冲突和版本不兼容给出稳定诊断，不能按 classpath 或注册顺序碰运气。

默认装配必须可复现；显式配置只用于覆盖部署选择。支持展示不含秘密的装配计划和实际能力，不把动态插件 manifest 强行扩展成任意核心领域启动器。

当前实现采用实现模块配置类上的 `@PlatformModule` 和 `META-INF/simplepoint/modules.imports` 索引。`requires` 表示本地必需依赖；`consumes` 表示可远程解析的契约，两者分开验证。一个模块的独占组件包不得与 catalog 中其他模块重叠，避免父包扫描误启未选模块。

`ModuleCatalog.plan` 返回本地计划及外部能力需求；`deploy` 验证完整宿主分配并生成每个宿主的远程路由。完整分配禁止同一逻辑模块同时属于两个不同服务，同一服务的多个实例不受此限制。这些纯规划 API 不负责授予凭据、搬迁数据或发布配置。

Spring 适配 `@EnablePlatformModules` 按选中闭包扫描、注册路由代理并校验提供方与声明一致。它适用于没有全局业务包扫描的新入口；原服务仍需逐项迁移基础设施、存储与入口贡献，不能只叠加该注解便称为完成组合。

模块的非秘密平台默认值使用 `META-INF/simplepoint/modules/{id}.properties`，在组件条件判断之前加载，仅为 `simplepoint.*` 提供最低优先级默认值。部署显式配置始终优先；模块默认值之间发生冲突时停止装配。默认值不能携带凭据或用于自动恢复授权。

启动注册使用模块声明中的 `initializers`。可复用初始化器声明所需接口，规划器自动并入拥有方的消费集合，
框架为每次模块初始化提供固定身份且限制契约的上下文。共享注册器不另建一个独占宿主的伪业务模块，
也不回退到宿主账号。模块资源使用唯一、精确、有限大小的路径和明确索引，只读取选中模块的声明。
先准备所有选中贡献，再按基础数据、声明注册阶段执行，同阶段保留任务优先级及稳定的模块依赖顺序。
必需初始化失败使 Boot 启动失败；初始化登记使用 `module/{id}` 稳定键，既有记录更新受事务锁保护，
不确定 RUNNING 状态禁止自动重放。旧宿主登记必须先迁移，不能因新键不存在就重新执行。registry 已提供本地预览/接管端口，在同一事务保留源记录、建立目标完成状态及持久接管回执；RUNNING/FAILED/冲突来源拒绝自动接管。
业务修改与远程登记不宣称跨模块原子提交，迁移/恢复自动化仍在 S3/S5 完成。
字典注册使用专门的拥有方持久完成状态，与字典/选项同事务提交，不走远程通用 RUNNING 登记。
其初始化器在 BOOTSTRAP 阶段提交精确批准声明；相同内容换宿主/重启不重复刷新，旧数据须先显式接管。
现有微服务保留兼容注册路径，模块入口抑制旧全量扫描注册器。

### 3.3 调用与授权

本地和远程都进入同一逻辑调用边界，携带经宿主验证的调用方身份与有界最终用户作用域。浏览器参数、客户端 header、可伪造的 ThreadLocal 标记不能自行提升为服务身份。

保留服务端方法和数据权限；本地调用不得取消现有受信调用校验。调用完成/异常后恢复全部安全及租户上下文，不残留到线程池下一次任务。

当前已实现隔离本地传输：新组合入口自动开启，原宿主暂保留兼容方式。每次调用使用不继承线程上下文的虚拟线程，
同一 JSON dispatcher/codec 处理参数、结果和契约错误；调用方事务不传播，提供方自己的事务仍由领域管理。
并发额度按完整调用树持有，嵌套沿用截止时间并限制深度；超时不重放写入，不提前释放仍运行任务的额度。
宿主停止时拒绝新调用并请求取消，不能将取消当作业务回滚确认。

资源服务器适配使用宿主的出站服务令牌，通过同一 JWT 解码器、受众/撤销策略和服务 scope 校验；HTTP RPC 入口也拒绝用户授权类型令牌。
新组合入口进一步使用 prototype 客户端工厂，从 Spring 注入点与模块包/ClassLoader 归属绑定逻辑调用方；所有客户端消费必须声明 `consumes`。
构造、字段、工厂、延迟及 ObjectProvider 注入均支持，嵌套本地/远程调用使用各自的模块凭据缓存，退出后恢复外层选择。
不接受请求携带的调用模块，也不回退到宿主账号。安装器客户端创建、秘密分发、领域 caller allowlist 自动派生和旧宿主迁移尚未完成，
禁止用统一超级服务账号或伪造 client_id 绕过领域验证。共享 API 的启动贡献须按 G21 接入归属，不能为无归属消费者偷偷选择默认模块。


仅纯服务契约支持位置透明。DAO、JPA entity、懒加载集合、事务资源不得跨边界。遗留契约逐项识别并迁移，不能将全部 Bean 暴露为 RPC。

### 3.4 事务和数据

领域事务边界与宿主拓扑无关。合并部署不能偶然将两项原独立提交操作合成一个事务；拆分不能将原子聚合拆成多个普通 RPC。业务幂等和持久操作状态继续有效。

模块可以共用一个物理数据库，但表和迁移有唯一逻辑拥有方；也支持绑定不同数据库。支持范围需由真实数据库测试证明。持久事件 outbox 必须与所属业务修改绑定同一数据库事务。

默认安装自动生成迁移计划和依赖顺序；已有部署的破坏性迁移不隐式执行。运行账号不因装配而自动获得建库或跨域权限。

### 3.5 HTTP、前端与认证

保持 `/common`、`/app`、`/dna`、`/workflow` 等逻辑公共路径。模块可重定位到不同宿主；前端无需随物理服务名修改业务 URL。

领域 REST 和前端产物从服务启动器中提取为可复用贡献。一个聚合宿主可挂载多个命名空间及 remote，发行校验遍历全部贡献，拒绝资源覆盖或遗漏。

HTTP 首批已实现独立适配模块与 `@ModuleHttp`：工作流 `workflow-http` 本地依赖 `workflow`，仅选择领域模块不启用浏览器控制器。公共路径与接口内部路径分开；Servlet 适配覆盖所有 MVC 映射器并核对实际挂载，规划阶段拒绝冲突。`DeploymentPlan.httpRoutes()` 派生逻辑路径到物理宿主，但当前尚未自动写入网关配置。

共享历史前缀已支持通过 `ModuleHttpRoutes` / `ControllerHttpRoutes` 从选中控制器的类型级映射派生互斥子树，包含别名、组合注解及继承声明；纯规划层不依赖 Spring。Common 中身份、OIDC、国际化真实控制器的拆分/聚合路由规划已验证，保持既有 URL。身份/OIDC/国际化生产 HTTP 模块已完成依赖与扫描边界接入，Common 原样复用其控制器。**S4 仍需完成**其他领域控制器的模块提取及完整权限资源/翻译贡献接入，不能把规划或模拟装配测试视为已完成生产业务验收。HTTP 适配模块 ID 不得覆盖已有资源拥有方，尤其不能把历史 `workflow` 资源改名为 `workflow-http`。

单体集成认证、浏览器会话、CSRF、资源服务器和协议端点；选择合适的统一 Web 宿主适配。原 WebFlux 网关保持独立部署支持，不直接混入同一个 MVC 安全链。认证密钥、会话生命周期、租户切换和授权刷新行为必须保持。

AI/MCP 的凭据保护、协议会话及工具隔离继续适用。单体只合并平台应用，不把不可信工具执行纳入主 JVM。

### 3.6 配置自动化原则

开发者添加模块依赖及最小声明后，框架发现配置。为默认单体提供集中环境参数；模块贡献可生成路由、订阅和运行检查清单。生产凭据来自环境/秘密管理，不生成公开默认密码，不自动扩大授权。

自动化包含冲突检查、可解释诊断和可重入安装。发现环境不可用时区分业务 readiness 与基础设施健康，MQ 暂停仍按现有 outbox 恢复规则处理。

### 凭据边界迁移（2026-10-20）

- `simplepoint-plugin-rbac-credentials` 独立承载凭据 RPC、Redis 会话与持久审计；共享 `rbac-authentication` 仍不依赖该适配器或 OAuth 服务。凭据适配器属于 identity，未新增一个必须单独部署的领域。授权服务发行依赖门禁禁止意外携带该提供方。
- 新 `security.credentials:1` 只接收显式凭据 DTO，复用同一密码/限流/账户状态/MFA 策略。成功凭据为随机 256 位、固定有效期、绑定已验证服务调用方的句柄；Redis 仅存调用方+句柄散列索引及用户/版本/到期信息。到期、账户变化及撤销不能继续使用。
- DNA 不再读取 `User.password` 或注入 `PasswordEncoder`。每次服务器操作复核凭据、真实租户成员关系与最新数据源授权，重新计算授权上下文；操作使用不可变快照，关闭后的连接不可复用，执行后恢复外层安全与授权上下文。元数据缓存仍可复用，但必须先验证 METADATA 授权，按实际可见数据源及分布式版本分区。
- JDBC 两端支持 `oneTimeCode`，密码不再被 trim；认证尝试不自动重放，传输对象在首次尝试后释放密码/OTP 引用。CONNECT 后首次授权失败会关闭新会话。协议补充稳定错误码、翻译键及 SQLState；旧读取者仍可读取 `errorMessage`。
- 成功/失败审计写入 identity 的事务 outbox（历史 producer `common`），审计拥有方通过独立 `credential-audit` inbox 处理。审计提交失败不返回会话；Redis/SQL 之间没有伪装成分布式原子事务，未暴露且清理失败的句柄仍会到期。事件声明及部署队列模板已更新；没有修改运行环境 MQ。
