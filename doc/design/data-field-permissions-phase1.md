# 数据权限与字段权限第一阶段实施清单

目标：让角色的页面资源授权可以绑定基础数据范围与字段规则，并在受支持的 JPA 查询和 HTTP 输入输出上实际生效。未配置页面规则时保持既有授权语义；已配置规则不得被不支持的查询静默跳过。表达式阶段复用规则解析到 ORM 谓词的扩展点，不把用户输入拼进 SQL。

- [x] 盘点页面资源、实体和接口，建立显式的页面能力目录；只对已验证的 JPA 入口开放规则编辑。
- [x] 在角色资源授权上绑定租户内有效的数据范围和字段规则，支持读取、修改、清除、乐观冲突与授权版本刷新；撤销页面授权时清理关联。
- [x] 将页面授权解析为请求内的有效权限，按已授权角色合并，并保持角色级旧规则兼容；无效规则拒绝使用。
- [x] 用 JPA Criteria/Specification 在列表、计数和单条查询上执行数据范围；写入前核验目标记录及目标范围；集中谓词编译入口。
- [x] 字段规则贯通元数据、响应、查询字段及写入；敏感字段的隐藏、脱敏、只读语义一致。
- [x] 把资源授权抽屉的两个预留入口改为实际配置与回显，并在提交前展示最终授权和规则。
- [x] 补充跨角色、租户隔离、并发冲突、分页/单条/写入、字段读写的测试；运行后端测试、前端类型检查并更新本地代码。

第一阶段数据范围使用现有 `ALL`、`SELF`、`DEPT`、`DEPT_AND_BELOW`、`CUSTOM`（指定组织集合）模型。表达式语法、跨服务原生查询和非 ORM 存储不在本阶段假装支持；能力目录明确标识不支持项。

能力核对：`dna.data-assets.view` 实际属于仅 `PLATFORM` 的资源目录，租户角色无法授权该页面，不能作为租户级数据权限试点。第一阶段数据规则仅开放租户页面 `organizations.view`；字段规则开放 `users.view` 与 `organizations.view`。其他页面仍显示不支持，不能把尚未接入的查询误标为生效。

`organizations.view` 的行范围以组织实体的 `id` 为范围字段，`SELF` 以组织创建人为范围字段。主列表、计数、树、选择器、表单草稿选择、详情和组织写入均应用同一规则。组织管理右侧的成员及候选成员查询在有页面规则时使用 JPA Criteria，按所属组织与可见组织求交；未配置页面规则的旧查询行为保持不变。无权访问的父组织下若有可见子组织，该子组织成为可见树的根。组织新建在 `ALL`、`SELF` 或包含本人数据时允许；纯 `DEPT_AND_BELOW` 仅可在已授权父组织下新建，`DEPT` 和固定 `CUSTOM` 禁止创建会立即不可见的新组织。

`DataScopePredicates.compile` 是后续规则表达式进入 JPA Criteria 的集中入口。规则来源与有效角色合并仍在授权上下文层完成；未来新增表达式 AST 编译时扩展这个入口，保留租户/软删除等外层强制谓词，不拼接用户 SQL。
