# 页面数据权限、字段权限和表达式

本次将权限能力从组织/用户页面的固定名单移入平台元数据与执行层，并补齐规则管理界面。数据规则始终与租户边界、软删除条件及资源授权取交集；字段规则在查询、输出、表单和写入端执行。

## 应用资源配置的分页读取（2026-10-10）

`GET /resources/children` 的目录、总数、搜索结果和子节点标记使用同一服务端可见性条件，
每页最多 100 项。平台管理员配置应用时保留全部资源作用域及可展示的停用项，停用项仍不可勾选；
非平台请求按当前空间的作用域、租户套餐—应用—资源有效关联和公开资源筛选，不要求调用者
已经拥有待分配资源。必要的启用结构祖先可供导航，但未获直接许可的祖先返回 `grantable=false`，
不会扩大可授权编码集合。这里只描述应用资源目录接口，不替代角色配置自己的目录约束。

分页只读取当前页的资源展示列，子节点判断只绑定当前页 ID，不加载资源实体或权限元数据。
隐藏/脱敏字段不参与关键词匹配；请求按不可读字段排序会在 SQL 执行前被拒绝。资源节点继承
真实源实体的字段权限，显示标签先投影源字段再选回退值，不能重新泄露原名称。

`GET /resources/subtree-codes` 在同一可见性边界内返回完整可授权编码，按原生 ID keyset 每批
最多 100 条，不将子树全部 ID 绑定进 SQL，也不把批次上限当成总数上限。平台应用配置保留
跨作用域授权语义；不可读的源 `code` 不允许通过字符串数组绕过字段权限。返回完整集合仍需
与结果规模成比例的内存，批次限制不代表常量空间。

既有 PostgreSQL 环境应在发布新查询路径前，逐条、在事务之外执行
[`20261010-resource-directory-visibility-indexes.sql`](../deployment/sql/20261010-resource-directory-visibility-indexes.sql)。
新安装的实体映射声明相同索引；没有这些关联索引，大目录的相关子查询可能退化为反复全表扫描。
浏览器回归使用真实控制器/H2/JPA/JSON 导出的 521 项目录首页、末页和完整子树响应；前端通过
共享 `normalizePage` 兼容原生平铺 PageImpl 和嵌套分页协议，不自行生成展示字段或表单提供器。

`POST /resources/assigned-tree` 将请求的已分配编码快照与当前有效许可取交集，复用候选目录的
作用域、软删除、源字段投影和排序规则。编码、必要祖先和祖先边图均按最多 100 项分批读取；
`checked` 只标记直接许可且实际选中的资源，结构祖先即使出现在请求中也不能借此获得许可。
子节点标记仅依据完整已分配边图，不因为同一父节点还有未选中资源就出现无效展开按钮。

当前层候选不超过 100 项时直接使用原生 SQL count/page；较大层按数据库多字段复合游标
每次读取最多 100 条薄索引，完整计算匹配总数，再以当前页 ID 读取实际展示列。升降序、
空值位置和字符串 collation 都由数据库决定，不在 Java 中合并近似排序。边图与当前层候选
仍占用与完整快照规模成比例的内存，较大层计数需要扫描该层索引；这里只保证 SQL 参数及
批次上界，不声称常量内存或固定查询工作量。浏览器首页和 501 项已分配集合的末页使用真实
控制器导出的响应，发生增删后仍按当前隔离快照验证分页收敛和原草稿归属。

## 标准接入

批量编码详情不是运行时鉴权。`POST /resources/by-codes` 使用真实
`findDirectoryResourcesByCodes` 目录快照：平台管理员保留所有作用域与可展示的停用记录，
非平台调用者仅得到当前作用域内仍有效的直接许可/公开资源。角色及当前用户等内部消费者的
`findAllByCodes` 则保留原运行时作用域口径，不因目录补齐而扩大可授权集合。两种详情都先以
最多 100 个编码读取必要标识与真实作用域，再以最多 100 个 ID 获取实际编辑/展示字段；
不加载实体或内部 `permissionMetadata`。不可读编码的公开查询在 SQL 前拒绝，名称受保护
仍可读取其他合法字段。批量身份补齐没有列表排序契约，不借受保护名称安排返回顺序。

构造登录上下文时使用显式作用域的鉴权编码查询，不能要求尚未建立的请求身份，也不能
沿用上一调用者的作用域或显示字段策略。`ResourceRuntimeQuery` 直接读取真实 EntityManager
的有界标量：集合最多 100 个编码；完整注册集合以 ID keyset 每批 100 条读取。
实际 enum-set converter 与 `ResourceScopePolicy` 决定资格，兼容旧空白/非规范 CSV；
这只是域枚举判断，不是 Java 文本排序近似。公开/组织空间标志只读 id/code，资源软删除
与停用均在 SQL 中排除。完整返回集合仍随后端注册规模增长，不承诺常量内存或固定工作量。

主资源管理树 `GET /resources` 复用平台 `ProjectionQuery` 的真实高级 DSL、列筛选、字段访问
校验和原生排序。当前空间可见性与根节点约束在用户条件树外取交集，并同样约束 count/page
和后代读取；隐藏的 `parentId` 不会让服务端自己的根约束变成非法公共筛选。保留已声明的
200 行分页上限，根索引、展示列与完整后代均以至多 100 项分批查询，不绑定整棵后代 ID 树。
管理投影保留说明、方法、路径、路由类型、插件及审计字段，避免编辑表单丢失真实存量值；
不读取内部 `permissionMetadata`。导航构造器可提升孤立节点，但分页管理结果仅保留实际
被计数的根，不能因不可见中间节点而把后代提升为未分页新根。完整树响应仍随后代规模增长。

资源管理的独立浏览器门禁使用真实 Spring schema 注册器、生产生成器与 HTTP/JPA/JSON
导出的 schema、521 根节点首末页、筛选结果及真实作用域字典选项；只移除行数据中的非确定
审计时间，不删改 schema 或查询能力。该门禁实际打开 `system/Resource` 的标准表格与
SForm，验证原说明保留，不把仅成功加载模块视为页面功能验收。

使用 `BaseController + BaseServiceImpl + BaseRepositoryImpl` 的页面，注册时由控制器实体类型与根 GET 的资源声明自动生成 `Resource.permissionMetadata`。角色资源配置依据实际注册的能力展示数据和字段规则槽位，不再维护页面编码白名单。服务端选择当前页面资源，不接受前端指定权限上下文。

默认所有者字段为 `createdBy`，组织字段为 `createOrgDeptId`。特殊实体可通过 `@PermissionModel` 指定字段；组织实体使用 `id`。权限配置本身等基础设施模型通过注解明确关闭不适用的规则槽位。字段规则目录合并本地实体和各服务已注册的实体/投影字段。

列表、分页总数、主键读取、创建、更新前后状态、删除使用同一规则。显式配置的页面规则也约束管理员；没有页面规则时保留原业务管理边界。查询条件、隐藏/脱敏字段的筛选排序均不能扩大权限。

关联查询需要真实字段映射，不能从前端列名猜测数据库归属。非标准控制器用 `@PermissionPage` 声明页面与投影模型，投影用 `@PermissionModel(page=..., owner=..., department=...)` 指定口径，并通过 `ProjectionQuery` / `DataScopePredicates` 执行。租户成员已适配为租户成员关系中的组织与用户标识；组织成员的查询和修改使用独立的组织页面接口。全局用户账号的历史组织字段不再作为租户成员数据范围。

一个页面使用多个实体时，表达式仅开放类型兼容的公共字段，并取各模型支持操作符的交集。外部存储、原生 SQL 或自行拼装 Map 的接口不能仅靠前端封装获得行权限：必须提供执行适配和字段投影。没有注册执行能力的页面不会显示可配置的数据规则槽位。

## 规则管理

数据规则页面修正了预览区与列表的伸缩布局，创建默认选择 SELF，CUSTOM 使用可分页组织选择器，EXPRESSION 提供目标页面与表达式编辑器。当前生效预览展示页面级数据和字段规则，同时保留旧角色默认范围的诊断信息。

已绑定的规则不能删除；已绑定规则更换类型或目标页面前需要解除绑定。创建/更新与字段条目保存均校验租户归属并刷新授权版本。新页面绑定标记 `pagePolicy=true`，不再被合并成影响其他页面的旧角色默认规则。已有 null 标记保留旧版兼容口径。

字段权限的新增、编辑和“配置字段规则”使用同一个编辑器：先选择已授权且有字段元数据的页面资源，再多选字段并添加访问级别。页面名、字段名复用注册元数据与国际化；同一页面多个模型保留各自的模型标识，后端存储仍使用规范模型名与字段名。选择页面用于发现字段，规则仅在角色资源配置中绑定后生效。

字段目录的展示标题必须先投影真实源字段，再选择可读的回退值。平台目录和 `PageFields`
使用 `Resource.alias/title/name/label`，保留原本的国际化标题口径；自定义租户目录的名称与图标
则属于 `TenantResource`，不能套用平台实体的字段命名空间。隐藏的候选不能回流为标题，
脱敏候选保留 `***`，不相关的隐藏字段也不能遮掉合法可读的回退名称。规范页面编码与模型键
仍用于已授权的元数据发现和规则存储，不把这些执行标识当作展示名称。

权限摘要中的普通 map 不会自动获得实体字段身份。`PermissionPresentationService` 对用户、
租户、角色、数据/字段规则和组织名称显式使用真实源字段投影；用户昵称与邮件分别保护后
再选择回退，不能靠 SQL `COALESCE` 抹掉归属。隐藏的名称不进入摘要，脱敏名称不能被原值
恢复。规则名称按唯一 ID keyset 每批 100 条完整读取，只取必要标量，不加载整份策略实体。
`DataScope.customDeptIds` 是实际 `ElementCollection`：应独立关联读取，每次最多 100 个规则
ID、100 个不同部门结果，不能把集合当标量选择而丢失零部门规则。组织展示查询的展开集合
同样最多 100；完整摘要仍需要与实际结果规模成比例的响应和内存。

受保护摘要的浏览器验收同时消费真实 Spring schema 服务、JPA 和控制器导出的对应 schema、
根列表、有效权限与摘要；核对真实平台列表及权限预览的 MASKED/HIDDEN 展示和合法元数据
保留，不在浏览器伪造隐藏策略或用另一上下文的未保护列表替代当前响应。

`GET /field-scopes/page-catalog` 保留完整授权页面目录接口；编辑器按 `/resources` 分页导航，仅按选中编码读取 `/page-fields`，不在打开时加载完整目录。`POST /field-scopes/configuration` 与 `PUT /field-scopes/configuration?id=...` 在同一事务中保存名称、描述和字段条目，避免产生仅保存名称的半成品。后端只对新增或访问级别变化的规范模型字段校验一次：授权页面元数据每批最多 100 条，只收集本次所需字段，多个页面可共同提供同一模型的字段，全部找到后停止读取。旧配置中已下线或暂不可访问的字段可原样保留或移除，不能在缺少元数据时更改访问级别。

旧 `/catalog`、`/entries` 的全局注册口径与新配置的页面授权口径不同，不按当前页面授权偷偷缩减旧目录。全局目录按唯一资源编码进行 keyset 分批，每批最多 100 条且完整返回；旧条目保存只解析所需模型字段，已知本地规范字段不读取远程目录，本地缺失字段仍允许远程注册补充。简名必须检查完整目录的唯一性，包含没有字段的同名模型；精确模型键优先于简名。端点各自校验完成后共用持久化路径，复用既有条目行、删除孤儿条目并刷新当前租户授权版本，不再把新配置重送旧全局目录校验。

多个服务可能携带同一资源声明，没有页面控制器的服务不会用空值覆盖页面所属服务发布的权限元数据。

## 表达式与可视化

使用 [ANTLR Java 工具与运行时](https://www.antlr.org/download.html) 生成解析器，语法文件位于 `simplepoint-core/src/main/antlr/PermissionRule.g4`。解析结果复用平台 `QueryDocument.Node`；执行复用带参数的 JPA Criteria 谓词，表达式不是 SQL。

支持 AND、OR、NOT、括号、等于/不等于、大小比较、IN/NOT IN、CONTAINS/NOT CONTAINS、IS NULL/IS NOT NULL。字符串使用 JSON 双引号，数字、布尔值和日期按注册字段类型校验。数值也可使用严格校验的字符串保留大整数与小数精度。

```text
createdBy = $user.id
id = $user.organizationId
id IN $user.organizationIds
name CONTAINS "研发" AND enabled = true
NOT (description IS NULL)
```

可用变量为 `$user.id`、`$tenant.id`、`$user.organizationId`、`$user.organizationIds`。组织变量来自后端验证的当前租户成员关系；当前模型只有一个主组织，因此 organizationIds 为该主组织组成的列表，不含下级组织。内置“本组织及下级”规则继续提供组织树范围。

每条规则最多 8192 字符、32 个 AST 节点、4 层分组，固定值列表最多 100 项。仅允许目标页面注册的字段/操作符；没有任意 SQL、反射、方法执行、任意属性链或外部调用。缺失上下文值遵守 SQL UNKNOWN 语义，包括 NOT；写入校验使用相同的三值逻辑。不同角色的表达式与内置范围按现有并集语义组合，最终仍与租户条件相交。

文本与可视化通过同一校验接口往返转换。可视化复用平台条件树和类型输入组件，修改草稿后须应用才能保存，避免把未应用的旧表达式提交。服务端在保存和角色绑定时再次验证，表达式规则只能绑定其目标页面。

接口：

- `GET /data-scopes/expression/catalog`：当前用户可访问且已注册的页面及模型字段。
- `POST /data-scopes/expression/validate`：提交 `resourceCode` 与 `expression` 或 `ast`，返回规范表达式和 AST。
- `GET /data-scopes/effective`：当前工作空间已保存的有效规则。

## 权限配置的显示与交互（2026-09-22）

字段权限抽屉左侧放置基本信息和资源目录，目录按层级分页，每页 15 项，只展示当前用户已授权且有字段元数据的权限点及其祖先。租户采用自定义资源体系时使用该租户的目录。`GET /field-scopes/resources` 返回当前层分页，`GET /field-scopes/page-fields?code=...` 仅返回选中权限点的字段。目录筛选在服务端基于资源元数据计算，再分页返回；这不是业务数据表的全量查询。

右侧字段不分页，采用虚拟列表和内部滚动。每行以翻译后的字段名配合编辑、可见、脱敏、隐藏四选一，单选分组按模型和字段唯一命名，互不影响。清除设置表示不再覆盖该字段。切换资源、翻页和切换语言都不清除表单草稿，最终仍通过原有配置接口原子保存名称、描述与所有字段规则。

`GET /data-scopes/presentation` 根据服务端已验证上下文提供资源、规则、组织和当前身份的显示名称，规则与组织名称按租户约束。编码、模型类名和字段标识保留在请求中，不作为界面缺失名称的兜底。显示名缺失时使用国际化占位名称。

表达式文本使用 `【字段名称】` 和 `@【上下文名称】`，与后端规范表达式双向映射。字符串字面量保持原样；重名字段增加序号以保持映射唯一，无法识别的字段不能提交。可视化、列表与生效权限预览复用同一名称解析。

已有环境需要执行 `doc/deployment/sql/20260922-permission-labels.sql` 更新旧内置文案。脚本仅替换仍等于旧默认值的记录，保留管理员自定义翻译；新安装直接注册随服务发布的翻译文件。

验证涵盖：资源树授权边界与分页、字段读取授权、名称目录租户隔离、表达式显示往返转换、真实浏览器新增和编辑保存、清除字段、切换资源保留草稿、中英文切换，以及现有前端模块回归。

## 2026-09-23：插件 HTTP 映射执行权限规则

插件控制器由 `ServletMappingPluginInstanceHandler` 独立注册。只使用
`WebMvcConfigurer.addInterceptors` 会漏掉该映射，导致授权上下文已有页面规则，但实际
SQL、JSON 投影和 schema 未选中页面规则。`ResourceServerAutoConfiguration` 改为注册
全局 `MappedInterceptor`，由默认 MVC 和插件映射共同发现；响应完成及异步切换均清理
`ResourcePolicyContext`。回归测试必须通过真实插件映射发起 HTTP，不能手动设置页面上下文来
代替这段集成链路。
