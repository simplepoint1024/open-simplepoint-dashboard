# DNA SQL 控制台修复与布局调整

## 变更

- 参考 [DataGrip 查询控制台](https://www.jetbrains.com/help/datagrip/query-consoles.html) 的数据库浏览器、编辑器、结果区布局，采用可拖动分区、紧凑工具栏、主题联动和自适应结果高度。
- 控制台执行目标改为启用的数据源，移除对旧 federation catalogs 列表的依赖；完整读取分页数据源列表。
- Ctrl/⌘+Enter 执行选中 SQL，否则执行光标所在语句；自定义按键优先于编辑器默认插入空行操作。此行为不是批量脚本执行，服务端仍校验 SQL 和查询权限。
- 查询与导出共享同步互斥锁；失败清空旧结果，并在结果区保留错误详情。树节点失败可以显式重试，不自动循环请求；刷新防止旧请求覆盖新树。搜索仅过滤已加载元数据，不扫描远程数据库。
- 双击元数据插入转义后的完整标识符，并替换当前选区。切换菜单保留草稿，关闭/刷新受未保存保护；查询参数浮层在非活动菜单隐藏。
- CSV/JSON 导出当前结果快照，不重新执行已经改动的 SQL。CSV 处理字符串公式注入，JSON 保留列定义及二维行数组（包括重复列名）；导出仅包含已返回行，不能绕过策略截断。
- 结果分页可以切换每页行数，新查询重置分页；系统导航默认从 180px 调整为 240px，尊重用户已保存的手动宽度。

## PostgreSQL 根因及修复

本地数据源实际连接 `simplepoint` 数据库，但旧联邦注册过程枚举所有可见数据库并立即尝试建立连接。PostgreSQL 元数据中可见的库不等于当前客户端通过 HBA 规则可访问的库；因此访问无关的 `postgres` 库失败后，整个注册过程失败。

查询现在只挂载当前库，以及 SQL 表路径或默认 Schema 明确引用的其他库。缓存键包含各数据源的数据库范围，防止窄范围缓存错误复用于跨库查询。显式访问受限库仍返回连接错误，不吞掉授权失败，也不修改或扩大 `pg_hba.conf`。

- 使用 DNA 网络命名空间和应用已有数据库凭据进行只读实库验证：普通三段路径及包含 `simplepoint` 的四段路径均能查询平台表，重复查询命中缓存；显式请求 `postgres` 仍被原 HBA 拒绝。未写入业务数据，未修改数据库访问规则。
- 浏览器业务接口使用隔离 fixtures；不能将这些结果当作真实账号写入式端到端测试。
