# Workflow 可视化设计与运行手册

## 适用范围

Workflow 工作台用于编排已经发布的 Agent 与 Skill 不可变版本。运行时只接受受限的声明式 DAG，
不执行脚本、命令、容器入口或页面代码。定义、版本、依赖快照和执行均按平台或租户作用域隔离。

## 从设计到运行

1. 新建 Workflow 定义。代码创建后不可修改，名称、说明和启用状态可维护。
2. 创建版本，从节点面板添加 Agent、Skill、人工任务、等待、条件、并行和结束节点。
3. 在属性面板固定已发布的 Agent/Skill 版本并连线。画布即时阻止自连、重复连线和环路。
4. 在“契约与治理”维护输入/输出对象 Schema、时长、节点数、并行预算、失败与补偿策略。
5. 在“确认创建”检查节点、连线、依赖和相对上一版本的变化。创建后的 Manifest 与依赖不可修改。
6. 发布草稿后它会成为活动版本。废弃活动版本会阻止新执行，但不影响已经开始的执行。
7. 使用 Schema 表单启动执行，在详情中查看节点检查点、人工任务和追加式事件时间线。

## 草稿与高级 JSON

- 画布修改自动保存到当前浏览器；关闭前会确认，下次打开同一 Workflow 可恢复。
- 撤销、重做和自动布局只影响当前设计会话；版本创建成功后浏览器 Manifest 草稿会清除。
- 高级 JSON 可维护可视化面板尚未覆盖的声明；返回画布前必须是有效对象，服务端仍会完整校验。
- Schema 字段名为空、重复或 JSON 无效时不会清空表单，也不会静默使用旧 Schema 创建版本。

## 节点与控制语义

| 能力 | 行为 |
| --- | --- |
| Agent / Skill | 必须固定资源和已发布版本；发布时再次校验内容 Hash 与作用域 |
| 人工任务 | 持久化待办、输入 Schema、截止时间和超时动作；响应提交后不可修改 |
| 等待 | 使用持久化定时检查点，不依赖浏览器保持在线 |
| 条件 | 只支持 `all`、`any`、`not`、`equals`、`notEquals`、`isTrue` 的有界对象表达式 |
| 并行 | 受版本固定的最大并行度约束 |
| 补偿 | 可固定补偿 Skill；`REVERSE_SUCCEEDED` 按成功节点逆序执行 |
| 暂停/恢复 | 协作式控制，在安全检查点暂停；恢复从持久化检查点继续 |
| 取消 | 不可撤销，同时取消仍开放的人工任务 |

Workflow 不提供伪造的浏览器端“单步执行”。调试依据是服务端节点检查点、输入输出、尝试次数、
失败码和追加式事件。页面对非终态执行静默轮询，并使用事件游标增量读取。

## 可靠性与安全边界

- 启动必须提供幂等键；同键同输入返回原执行，同键不同输入拒绝。定义行锁避免并发重复创建。
- Manifest 最多 1 MiB、128 个节点、512 条边；条件深度、执行时长、节点执行数、并行度和载荷均有上限。
- 运行计划保存固定 Manifest 与依赖内容 Hash；Worker 使用租约、心跳和持久检查点恢复。
- 管理、查看、执行、干预分别使用权限点；跨作用域资源统一按不可见处理。
- 生命周期、版本、启动及人工干预写入不含输入输出或凭据的结构化审计日志。
- Worker 提供领取、成功、失败和耗时等 Micrometer 指标；执行和节点检查点保留失败定位信息。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 无法选择 Agent/Skill | 先在相同作用域发布依赖版本，并确认资源启用 |
| 创建版本被阻止 | 根据画布诊断与契约页修复连线、依赖、条件、Schema 或预算 |
| 发布失败 | 依赖可能已停用、废弃或快照不一致；选择新版本后创建新的 Workflow 版本 |
| 执行一直等待 | 查看人工任务、等待节点或子执行状态；详情页会自动追踪 |
| 暂停后仍短暂运行 | 正在运行的子任务到达安全检查点后才进入 `PAUSED` |
| 重试后出现重复执行 | 调用方应重用原幂等键；页面每次新提交自动生成新键 |
