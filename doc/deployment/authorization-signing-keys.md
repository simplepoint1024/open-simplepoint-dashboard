# 授权服务签名密钥与 RPC 认证恢复

授权服务正式部署必须设置 `simplepoint.authorization.signing-key-set-file`（环境变量 `SIMPLEPOINT_AUTHORIZATION_SIGNING_KEY_SET_FILE`），指向只读挂载的私密 JWK Set 文件。文件置于持久化秘密存储，限制为服务 UID 可读；不得写入 Git、镜像、Consul 明文配置、日志或验收证据。

- 文件最多 64 KiB，包含且仅包含一把用于签名的 RSA 私钥，至少 2048 位，`alg` 为 `PS256`，具有唯一且非空的 `kid`。`use` 如存在必须为 `sig`。
- 可同时保留旧的 **公钥**，用于验证轮换前已签发且未到期的令牌。编码器只选择私钥；JWKS 端点继续提供公开验证材料。私钥文件的备份同样作为秘密管理。
- 已配置文件缺失、损坏或含不合格密钥时启动失败，不生成替代密钥。未配置路径时保留原有开发环境临时密钥行为，重启将使旧签名失效；该模式不适用于正式使用。
- 所有授权实例使用同一版本的密钥集。轮换先分发新公钥，再切换唯一活动私钥并保留旧公钥，至少覆盖最大令牌有效期与时钟容差后移除旧公钥。不要将两把私钥同时设为候选。
- 首次从临时密钥迁移时先读取当前公开 JWKS，将其公钥保留到新文件；不要尝试导出运行进程内的私钥。

服务路由的 OAuth2 客户端收到认证边界 HTTP 401 后，仅使被拒绝的缓存令牌失效。若其他请求已刷新令牌，保留新缓存；获得不同的新令牌后只尝试一次调用。静态凭据不重复请求；403、业务失败、网络中断和超时均不触发重放。此机制不能替代业务幂等键，也不能替代持久化签名密钥。

部署验证应保留旧令牌于测试进程内，在授权服务重启前后验证同一令牌与公开 `kid`，同时核对 RPC 调用、普通用户访问和旧审批快照。验收产物只记录结果及公开密钥指纹，不记录令牌或私钥。
