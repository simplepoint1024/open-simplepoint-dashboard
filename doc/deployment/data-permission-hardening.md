# 数据权限加固上线说明

## 本次范围

已实现租户归属校验、认证后解析权限、版本化缓存、缺失执行上下文拒绝访问、独立角色范围绑定、字段读写与 Schema 共用策略、组织/用户变更刷新版本，以及当前用户有效策略预览。

本次代码测试使用隔离的 H2 数据库，没有迁移现有本地 PostgreSQL，也没有重启运行中的服务。

## 上线顺序

1. 备份目标库，确认当前库和 schema。审核并执行 [新增范围绑定表 SQL](sql/20260908-role-scope-binding.sql)。若表已存在，核对实际列和唯一约束，不能仅凭 IF NOT EXISTS 判断结构正确。
2. 查看脚本末尾的旧范围冲突清单。升级不会随意选择第一条策略，也不会自动覆盖旧授权。
3. 协调更新授权上下文提供方及全部资源服务。消费者现在调用 currentVersion 远程方法，不能只升级一端。
4. 构建并发布 common 前端及对应静态资源。角色范围页面改为统一保存，并携带 revision；旧客户端需要同步适配。
5. 使用普通租户成员、租户所有者和平台管理员分别验收：SELF、CUSTOM、ALL、换租户、换角色、权限撤销、字段 HIDDEN/MASKED/只读及缓存命中后失效。
6. 对业务自定义 SQL、Map 导出和远程 AI/DNA 模块逐个做接入测试；通用测试通过不等于这些入口自动受保护。

## 兼容变化

- 没有上下文的业务行读写不会再默认放行。后台任务需要可信的显式授权上下文或经审查的专用服务入口。
- 普通用户未绑定数据范围时为 SELF，不是 ALL。ALL 仍不能穿透租户边界。
- 新角色无需资源授权记录即可保存范围。清空后的独立绑定不回退读取旧记录。
- 旧记录有多个不同范围时，确认替换会同时覆盖数据/字段两个维度；请核对两个选择。
- 字段新增配置改用本服务实体目录，未知、重复及跨租户策略会被拒绝。
- MASKED 统一输出 ***，不再保留原值首尾片段。DTO 需显式关联资源；Map 投影需显式调用保护方法。
- 非可写 primitive 字段不再跳过创建检查；需要可空领域字段或明确的服务端创建策略。
- 普通字段范围 POST/PUT 仅修改元数据，规则走 /entries；前端已适配。
- 删除仍被角色引用的策略会使解析拒绝访问；先解绑，再删除。引用删除保护尚未加入。

## 边界与后续工作

后续平台账号拆分已将组织迁入租户成员关系，权限上下文不再读取全局 User.orgId；上线需同时执行 platform-accounts.md 说明的迁移。字段目录仅包含 common 持久化单元。预览展示当前用户的已保存有效策略，不提供任意用户模拟。跨服务目录汇总、单租户多组织成员模型、复杂嵌套 DTO/Map 适配及逐业务接口审计需要单独推进。

权限缓存每次复用前读取当前版本，增加一次版本查询/远程调用；上线后关注延迟与可用性。失败应拒绝请求，不应降级到旧权限。

## 回滚

SQL 仅新增表，保留旧授权列。但首次保存独立绑定后，旧程序不认识新绑定，可能恢复更宽的历史权限。不能直接回滚程序并假定授权不变。应停止权限配置写入，备份新绑定，逐角色审核并制定安全回填或前向修复方案；不要直接删除新表或批量取第一条旧策略。
