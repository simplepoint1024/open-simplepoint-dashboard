# 租户资源与套餐权益升级

本次升级把租户运行期资源读取迁移到租户目录及权益余额。个人和组织空间都需要完整准备状态；旧库不能只执行建表后直接对外提供服务。

## 已完成的升级演练

2026-10-23 从现有 PostgreSQL 18 只读导出一致性副本，恢复到独立的 PostgreSQL 18 实例。使用完整、固定的安装器发行目录执行迁移、审核、接管和原计划重复执行。

- identity 迁移从 V8 升至 V17，既有模块迁移校验通过。
- 13 个有效空间均完成历史权益接管，回读 `pendingTenantsRemain=false`；重复执行返回同一回执。
- 按原有列核对 221 张表，214 张保持相同数据指纹。变化只有 4 张安装日志表、租户目录、租户授权版本及 identity 迁移历史。
- 业务表、307 条有效资源授权、25 条已撤销资源授权的原有数据未改变。没有恢复已撤销授权。
- 使用新部署身份演练了安装器的 21 个模块调用客户端、6 个资源拥有方及 2 个字典拥有方更新。

副本、私有配置、审核指纹及原始日志位于本地 `.simplepoint/tenant-entitlements-20261023/`，不提交数据库内容、凭据或会话。以上为历史演练证据；正式更新结果见下文。

## 正式更新顺序

1. 完成相关测试及前端完整发行包构建，验证宿主 HTML、各联邦清单与引用资源，固定安装器发行目录和服务镜像。不要在安装中覆盖发行目录。
2. 入口进入维护状态，停止旧单体和相关微服务写入者，保留可恢复的一致性备份。保留 PostgreSQL、Redis、RabbitMQ、MinIO、Consul 及既有业务存储。
3. 使用同一发行目录执行 `migrate`、`verify`。核对源库和副本结构，不使用 ORM 自动改表或修复迁移历史。
4. 用新的部署 UUID、客户端凭据及准确预期世代执行 `provision-review`、`provision`。交付匹配的新运行配置，旧二进制不得使用新身份继续写入。
5. 保持外部维护状态，启动新单体，完成权威平台资源和基础应用成员注册。不得通过伪造租户 READY 状态绕过初始化。
6. 对已迁移的实际库执行 `tenants-review`，核对有效待接管空间清单后，以同一指纹执行 `tenants-adopt`。失败时保留原 UUID 和审核文件，按持久回执恢复，不能换 UUID 重发权益。
7. 启动其余新微服务。核验注册、登录、默认个人空间、负责人/普通成员、套餐叠加/撤销/到期、资源更新与下线、业务表单/流程、文件及 MQ 恢复。登录验证同时覆盖 home 和 single 入口。
8. 确认无遗漏空间、实际业务链路和前端资源均通过后解除维护，保存脱敏验证证据。

## 失败与恢复

维护期内优先修复并继续同一安装操作。缺少 ACK 的 RUNNING 操作不等于未执行，不得删日志或自动重放。旧镜像只能配合已核实的数据兼容性恢复；新系统接受业务写入后，旧备份不再是可直接执行的回退方案。

## 2026-10-23 正式更新结果

按上述协调顺序完成 V17 迁移、部署权限安装和 13 个历史空间接管。新注册个人空间验证后，14 个有效空间全部 READY。原有资源授权的 332 行指纹与升级前一致，包含 307 条有效授权和 25 条已撤销授权。

单体及微服务已更新并解除维护。单体和 8 个微服务使用 `20261023-tenant-entitlements-r3`，微服务 host 使用 `20261023-tenant-entitlements-r4`。R3 将授权版本服务的仓储实现从 tenant-api 移到所属租户实现模块；R4 补齐传统网关 `/auditing/**` 路由。镜像逐项校验完整发行目录，服务分发均包含前端。

新用户注册已验证，两个入口分别通过真实登录与负责人页面验证、六个联邦模块共 381 个资源哈希验证、会议室/日报/两档报销/驳回重提流程。开放入口后再次验证个人、组织、平台共 6 组登录和授权读取。隔离 PostgreSQL 已停止，原始备份、安装回执和测试账号会话保留在忽略提交的私有目录。

正式操作中发现 containerd 回收停止容器阻塞，在保留容器任务的配置下恢复守护进程后完成更新；基础设施容器继续运行。没有删除容器存储、改写业务历史或恢复旧数据库备份。完整结果、镜像身份、仿真记录 ID 和验证边界见[最终部署证据](../verification/20261023-tenant-entitlements-deployed.json)。
