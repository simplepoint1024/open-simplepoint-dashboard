# 国际化字段与租户资源名称

字段标题的翻译键与记录值的多语言内容分开管理。`@Schema(title = "i18n:…")` 描述字段标题；`@LocalizedField` 描述一个 `LocalizedText` 值，不能把租户输入作为平台公共翻译键写入消息字典。

## 公共契约

`simplepoint-api` 提供注解、值结构、语言规范化、长度校验与解析工具；`simplepoint-core` 提供 JPA JSON 文本转换器。公共值与解析工具不读取数据库、不调用租户服务。拥有该字段的领域负责保存、授权和事务。

```java
@LocalizedField(maxLength = 100)
@Convert(converter = LocalizedTextConverter.class)
@Column(name = "name_localization", columnDefinition = "TEXT")
private LocalizedText nameLocalization;
```

值包含 `defaultValue`、`defaultLocale` 和 `translations`。语言标识使用规范 BCP 47，接受输入下划线并规范为连字符，不接受扩展或私有语言标签。字段所有译文共用注解声明的字符上限，字符按 Unicode 码点计算；语言数有上限。领域写入时必须调用 `LocalizedTexts.validate`，不能依赖浏览器校验。JSON schema 以 `x-localized.version = 1` 声明编辑器契约，并包含嵌套字段约束。

`SForm` 自动选择公共 `LocalizedText` 编辑器。业务适配器提供已有平台翻译键、字段所属范围和稳定 owner；公共组件接受值、回调、可选语言和继承内容，不访问业务接口。普通输入编辑当前界面语言，地球图标打开可调整宽度的右侧抽屉。语言、译文、来源和恢复操作使用平台 `DataTable` / `TableActions`。

抽屉与主表单共享同一个草稿。取消恢复打开时的字段快照，完成保留草稿，最终由主表单一次保存。打开抽屉期间阻止主表单提交；关闭、页面切换和授权范围变化会停止所属读取，防止旧请求污染新空间。隐藏或脱敏字段不能打开译文读取；只读字段可查看，不能更改任何语言。

## 租户资源

租户资源的 `nameLocalization` 保存于租户自己的资源记录，跟资源修改、授权版本更新处于同一事务。沿用租户 ID 与资源 ID 隔离；平台资源定义和消息字典不被修改。该字段继承 `name` 的字段权限，不能借其他语言绕过只读或读权限。

显示顺序：当前语言的租户译文 → 语言级租户译文 → 当前语言的平台译文 → 默认名称。平台翻译键保留在目录定义中；前端只在派生的展示路由中应用租户覆盖，不改动路由、资源码、授权或导航缓存原始数据。资源列表与上级/目标选择器沿用相同解析规则。列表查询和排序仍使用声明的资源字段，不在浏览器重排服务端分页。

编辑默认语言同步更新默认名称；编辑其他语言只修改对应译文。恢复有平台来源的默认语言时同步恢复默认名称；其他语言恢复只删除该项租户覆盖。没有平台来源时使用默认名称。

检查平台更新始终保留租户译文。显式覆盖平台定义可以刷新默认定义，但不删除已保存的租户语言覆盖。未传多语言值的旧调用保留已有译文；旧调用修改名称时，按该请求语言建立覆盖。

## 升级与验证

identity V18 为 `simpoint_saas_tenant_resources` 增加可空 `name_localization TEXT`，通过平台迁移安装器执行。既有空值不猜测历史编辑语言，也不批量重写名称。已确认的历史名称问题通过正常租户负责人 API 修复并回读。

验证覆盖：schema 生成、Unicode 长度、语言规范化与重复标签、事务持久化、平台定义更新、旧客户端兼容、只读直接请求、隐藏/脱敏序列化、语言切换后的路由身份、抽屉取消/完成/保存，以及单体和微服务入口的真实运行。

## 应用表单与生成资源（2026-10-24）

表单普通字段、计算字段、明细字段、选项与组件标题使用可选 `labelLocalization`，复用 `LocalizedText` 与公共编辑器。字段默认名称必须等于该值的 `defaultValue`；字段与选项名称上限为 120 个 Unicode 码点、32 种语言。缺省 metadata 仍从 JSON 中省略，不能改变未扩展的历史快照摘要。译文参与文档摘要，但不改变字段 ID、列名、存储标签或计算表达式。

运行时只派生显示文档，原始草稿、发布快照和数据值保持不变。字段授权先于运行时投影：隐藏字段及其译文一起移除，脱敏选项不返回。业务列表 schema 通过 `x-title-localization` 携带已授权标题；公共 schema 展示层负责随当前语言刷新标题。新增、编辑、详情及审批只读表单复用同一运行时。

应用、页面与生成资源名称使用 `nameLocalization`，统一限制为 100 个 Unicode 码点。应用名称、页面名称及目录名称属于租户应用领域，不写入平台消息字典；生成资源同步到该租户的资源目录。旧资源声明不能在缺少完整多语言 metadata 时重命名已经配置译文的资源。

## 应用多级目录

入口为应用详情的“应用目录与名称”。同时支持挂到已有、当前有效的租户目录，以及应用内多级目录和页面归属。应用目录设置、应用/页面名称采用同一个草稿和同一次保存；列表、动作、选择器、表单和可调宽抽屉复用平台组件。目录上限为应用根目录加 99 个内部目录，内部深度最多 7 层，完整配置最多 500 个页面。删除内部目录前必须迁移其页面和子目录。

`app-form` 拥有配置与持久化待同步意图，`identity` 拥有实际资源树。跨域操作使用 `ManagedTenantResourceService`，网络调用不在应用本地数据库事务中执行。`applyNavigation` 在租户资源锁内验证完整图、来源、父级可用性、循环、稳定身份和版本，再原子更新层级与名称；页面 URL、资源码、生命周期代次、下线状态和授权均保留。

导航修订独立于表单发布代次。发布工作捕获导航修订，资源所有者拒绝旧声明覆盖新目录。完整请求摘要规范化语言映射与属性顺序，以支持单体、微服务间的安全重试。网络响应不确定时保留待同步配置，界面支持重试或取消；取消由资源所有者先持久化拦截该修订，再清除应用待办。已经生效的操作只确认完成，不反向撤销目录或恢复授权。取消先于首次创建时保留不可执行的资源身份占位，下一次有效配置可复用。

升级使用 app-form V2 与 identity V19，通过平台安装器迁移、校验；不得更改已发布的基线 SQL。现有应用在显式保存目录配置前保持原有挂载行为。导航配置成功后刷新当前授权范围内的页面和路由缓存，避免需要重新登录才能看到新名称或目录。

生成表单的字段权限描述同步携带可选 `titleLocalization`，包含明细前缀。注册、持久化、公共字段交集和权限配置展示均保留该值；所有授权键仍是模型 ID 与稳定字段 ID。该只读组合标题最多 255 个码点、64 个语言项（两个各最多 32 项的字段/明细语言集合），不会扩大权限或改变查询运算符。
