# 平台表格查询升级

目标：可靠覆盖业务列表需要的 Criteria 查询子集，不开放任意实体路径、SQL、关联或批量写入。

## 阶段 1：查询正确性

- 公共 JPA 查询与个人工作中心复用 `QueryPredicates` / `QueryValues`；个人字段白名单、条件数量和归属约束保持在领域层。
- `FilterCondition` 按最长操作符前缀解析，不再按最后一个冒号拆分值。ISO 时间、显式 `equals:`/`like:` 文本中的冒号原样保留。
- `is:null` / `is:not:null` 无需值；兼容旧 ConditionsBuilder 附加示例值的形式，新 Builder 只输出规范形式。
- `like` / `not:like` 表示不区分大小写的字面包含/不包含，转义 `%`、`_` 和转义字符。**不再将调用者输入视为 SQL LIKE 模式**；仓库调用审计未发现生产 Java 调用者依赖手写通配符。外部调用者如使用模式需迁移，不能在公共表格中直接输入 SQL 模式。
- 数字、布尔、枚举、UUID、日期按 Java 字段类型转换，非法值、溢出、倒序区间、空集合成员及不适用操作符拒绝执行。
- 字符串等值和排序比较保持大小写敏感；空字符串不是 NULL。NOT IN/不等于等遵循 SQL 三值逻辑，不自动包含 NULL。
- 专用领域可通过 `ProjectionQuery.prepareIgnoringCase` 显式保留原先的文本匹配规则；目前仅平台账号/账号审计使用该选项。它按字段归一化文本值与 SQL 表达式，不能整体转换 JSON 或改变公共默认语义。统一分页器遵守 schema 的 `x-query.maxPageSize`，后端仍独立执行分页预算校验。
- Instant 的纯日期值按 UTC 零点解析；完整时间须含时区。LocalDate/LocalDateTime 分别使用对应 ISO 格式，不猜测浏览器时区。按用户时区的“整天”筛选留待类型化日期控件阶段。
- 公共接口保留裸值等值查询；含冒号的等值文本须用 `equals:` 显式表达。未知操作符、未知字段不再静默忽略；`page/size/sort` 始终是分页传输参数，不作为实体字段筛选。同名业务字段须通过 `$query` 表达。
- 公共查询最多 35 个 Map 条目（含分页与服务端条件），单值最多 8192 字符，单列最多 100 个集合值；个人领域保留更严格限制。
- `InvalidQueryException` 通过异常转换链保留为 HTTP 400，输出稳定 `INVALID_QUERY` 和不包含用户值/SQL 的提示。
- 服务端软删除条件覆盖客户端输入；租户过滤及数据权限始终与用户条件 AND 合并。修复前公共解析器可能漏掉软删除条件，升级后历史软删除记录将正确隐藏，不删除任何记录。

验证：核心解析器单测、真实 Hibernate 的全部基础操作符、分页/count、软删除/租户/SELF/NONE 隔离、持久化异常转换和 MockMvc HTTP 400。数据库测试默认 H2；PostgreSQL 仅允许一次性 `jdbc:postgresql://127.0.0.1:45434/query_test`，禁止指向业务数据库。测试会创建并删除测试表。

## 阶段 2–6：已实现（2026-09-18）

### 结构化条件与能力声明

- 新增版本化 `QueryDocument`。保留原 GET、分页、前缀筛选协议；`$query` 参数接收 `{"version":1,"where":...}`，支持 AND / OR / NOT、同字段重复条件、类型化集合和区间。
- 表头也可以传单字段的同版文档，避免 CSV 拆坏包含逗号的值。空字符串与 NULL 明确区分；布尔 JSON 值不能用字符串代替。
- 严格拒绝重复 JSON 键、未知属性/版本、任意点路径、空条件组、超深树及超额集合。单次请求总计最多 32 个节点、4 层深度、8192 字符，单个标量最多 2000 字符、集合最多 100 项。前端还限制 URL 编码后的过滤内容为 6000 字符，为 GET 路由及分页参数留空间；超限显示提示，不放大网关限制。
- `@TableQuery` / `@QueryField` 是显式服务端白名单，并生成 schema 的 `x-query` 能力；隐藏/脱敏字段不得用于筛选或排序推断。可进一步缩小字段操作符集合，禁止排序。
- **已接入资源管理与“我的事项/待办/消息”。** 个人投影复用实体上的同一声明，不维护两份字段白名单；个人接口仍强制 owner/workspace/状态/回收站条件。普通 JPA 服务按原方式叠加租户、数据权限及软删除。
- 其他专用业务查询保留旧协议；没有声明 `x-query` 的页面不会展示未实现的高级查询能力。平台账号等专用实现的大小写语义不被此次改动替换。

### 表格交互

- 类型化数字、布尔、日期/时间、枚举、集合、双值区间控件；日期按浏览器时区输入，Instant 转成带时区的标准时间，LocalDate / LocalDateTime 保持自身语义。
- 字典列可以选择适用的等于、不等于、IN、NOT IN、空值等操作符。能力声明未开放的列不显示筛选或排序入口。
- 高级条件树、条件摘要、最多三列排序及优先级编辑都复用平台 Table / SimpleTable，不恢复顶部搜索栏。筛选和排序变化回到第一页；清除单列排序保留其他列。
- 用户可保存最多 10 个命名视图；复用用户偏好接口。按资源、租户、角色、上下文隔离，使用 SHA-256 生成有界键。只在打开工具抽屉时读取，不增加菜单关键加载路径。
- 偏好读取失败不允许覆盖保存，写入失败可重试；恢复视图前重新校验当前能力。切换权限上下文取消旧读取，抽屉只在当前标签页展示。

### 受控关联与统计边界

- `@QueryRelation` 显式定义关联别名、目标类型和相关键；结构化 `exists` 只能使用该白名单，最多一跳，不开放任意实体路径。
- 使用相关 EXISTS 子查询，目标记录另行执行租户、软删除及数据范围限制。不会通过主表 JOIN 放大行数，分页/count 复用同一过滤条件。
- 关联编译能力已用真实数据库验证；本次业务菜单没有默认开放额外关联。领域明确声明后可通过查询接口使用，不假装所有关联都已获授权。
- GROUP BY / HAVING、聚合投影、任意函数、任意 SQL 及批量更新不属于公共表格协议。首页个人统计继续使用已有专用 overview 接口，不增加通用聚合 SQL 入口。

### 分页与性能

- 通用 JPA 查询和个人查询统一稳定排序语义：空值在后、唯一 id 作最后的平局规则；最多三列用户排序，分页范围有界，count 不受排序影响。
- 保留后台列表的页码、跳页和总数语义，因此本次选择有界 offset 分页，不引入不适合这些页面的游标交互。若后续有无限时间线，再为该领域提供专用 cursor 接口，而非伪装成可任意跳页。
- 平面 SimpleTable 在一页至少 100 行时启用虚拟滚动；小页、树表、展开行与换行布局保留普通表体。调用方可用 `virtual={false}` 关闭。
- 数据库基准：一次性测试库 10,003 行、offset 9000、page size 20、10 次取页及 count；断言每次最多 2 条 SQL、实体加载不超过 20 行。H2 中位 14.68 ms、最慢 42.25 ms；PostgreSQL 中位 11.82 ms、最慢 13.46 ms。这些是本机测试环境结果，不代表外网端到端 SLA。

### 接口示例

```json
{
  "version": 1,
  "where": {
    "op": "and",
    "children": [
      {"field": "priority", "op": "in", "value": [1, 2]},
      {"op": "or", "children": [
        {"field": "title", "op": "like", "value": "发布"},
        {"field": "dueAt", "op": "is:null"}
      ]}
    ]
  }
}
```

`sort=priority,desc&sort=dueAt,asc` 按顺序定义排序优先级。必需权限限制永远位于用户条件树之外。

验证包含真实 Hibernate/H2/PostgreSQL 查询、非法条件、字段限制、租户/SELF/NONE/个人归属隔离、关联去重/count、多列分页，以及生产前端构建的隔离 API 浏览器回归。浏览器回归不等于使用真实账户操作业务数据。

本次验证结果：403 项后端测试（core 299、JPA 33、个人实现 13、个人 REST/schema 11、security-core 33、resource/router 14），145 项前端测试；六个前端工程类型检查、国际化检查、生产构建与 56 个 MF 暴露模块检查通过。core、data-jpa 和个人 API/实现/REST 的 Checkstyle 通过。浏览器用例覆盖筛选/多列排序、视图失败保护及恢复、100 行虚拟表体和 20 行普通表体切换，并保留原有首页、上传、个人工作中心和 SQL 控制台回归。

## 原路线与交付边界

### HTTP 字段权限与 Jackson 版本（2026-09-19）

- Spring Boot 4 的 HTTP 默认使用 Jackson 3；Jackson 2 的 schema mapper 和序列化模块不能替代它的字段权限。两套模块分别注册，但复用同一字段策略，不移除仍被 schema 使用的 Jackson 2。
- 回归必须验证生产 HTTP 转换器输出：隐藏字段不存在，脱敏字段不暴露原值，序列化缓存不能沿用上一请求的授权。单独验证 schema 或禁止筛选/排序不足以证明数据不泄漏。
- OAuth 密钥独立声明仅写入，保留 schema 中的密码输入；配置 DTO 不装载旧密钥。敏感字段不能通过查询或排序推断。原始 Map 无领域归属，专用投影仍须显式执行字段策略。

### 大文本查询存储适配（2026-09-19）

- Java `String` 不保证底层是普通 VARCHAR/TEXT。`@Lob String` 在 PostgreSQL 中使用大对象标识；直接包含查询会被 Hibernate 的 `lower()` 参数校验拒绝，直接按标识排序也不等于内容排序。
- `QueryExpressions.scalar` 在公共谓词及实体/投影排序入口统一转换已开放的文本 LOB 表达式。PostgreSQL 在 SQL 内解引用内容，H2 使用显式文本转换；字段白名单、参数绑定和外层权限条件不变。不修改现有映射或业务数据库。
- 回归应逐个声明字段执行查询与排序，并使用真实持久化回读值构造精确时间条件。已在 H2/PostgreSQL 验证 26 项 Common 主列表专项，包括长文本、中文、字面 LIKE 特殊字符、等值/集合条件、内容排序及分页计数。适用实体与剩余全平台验收见 `platform-table-coverage.md`。

### 资源管理高级搜索回归修复（2026-09-18）

- 入口日志确认 `name like Ho` 与 `sort=sort,desc` 组合返回 400。根因是 `@RequestParam Map` 的排序参数与实体 `Resource.sort` 同名，误进入整数条件转换。仓库统一排除传输参数；表头同名字段筛选合并入 `$query`，与排序独立，并校验合并后的深度/节点预算。
- 管理列表组装资源树后保留数据库根节点排序，导航菜单和子节点自然顺序不变。
- 加载失败仍保留筛选工具，提供重置筛选/排序；仅展示受控 `INVALID_QUERY` 校验文案，不展示 SQL/内部异常；400 不自动重试。
- 增加真实 ResourcesController → ResourceServiceImpl → Hibernate/H2 的复现请求回归，验证匹配结果、根节点边界、降序和 400 错误合同。生产构建浏览器回归验证失败提示、筛选入口保留及重置恢复；浏览器 API 仍为隔离测试数据，未使用真实用户凭据。
