# DNA / 表单 / Workflow 使用与运维

## 使用流程

1. 在应用工作台创建表单，设计字段、主场景及需要的弹窗/抽屉。网格布局负责展示；明细行负责有独立物理子表的业务集合。先保存、冻结版本，再发布到应用页面。
2. 在流程定义的“流程设计 → 配置变量”声明流程变量，选择 `simplepoint-app` 表单引擎、已发布表单版本和主场景。通过字段映射连接业务字段与流程变量。金额及大整数使用 `decimal`，不要改成 `number`。
3. 配置审批节点和参与人后保存并发布流程。任务默认继承启动时的业务表单；任务可以选择同一表单版本的展示场景。审批输入由流程变量声明控制，已映射的业务事实不允许在审批时覆盖。
4. 在应用运行页“提交审批”，或数据列表选择已有记录后提交；流程中心“发起”也会进入相同 APP 提交入口。完成主表、明细和流程输入后提交。
5. 在个人待办办理，读取当次不可变业务快照并填写审批意见/节点变量。提交记录提供流程进度与业务快照，显示技术处理状态及流程业务状态。
6. 驳回后通过“修改后重提”创建关联的新一轮提交。保留原表单、流程版本，重新检查当前权限及记录版本；旧审批证据不会被覆盖。

应用页面必须授权给使用人；审批参与关系并不自动授予整张业务表的列表、修改或删除权限。读取快照和审批仍检查当前页面与字段权限，撤权会立即阻止新的业务操作。

## 状态与故障处理

| 状态/现象 | 含义与处理 |
| --- | --- |
| ACCEPTED / PROCESSING | 意图已持久化或正在处理，等待处理结果；不要用新操作键重复提交 |
| RETRY | 后台按原意图重试，记录值、版本和业务身份保持不变 |
| ATTENTION | 连续失败达到上限，检查页面/目标库/流程可用性和错误码，再由原提交人在提交记录恢复同一操作 |
| SUCCEEDED | 提交协调已成功，不代表业务审批通过；另查 RUNNING / COMPLETED / REJECTED / WITHDRAWN / CANCELED |
| 409 | 当前记录/设计版本或幂等请求冲突，重新加载后明确选择新操作；不能改写旧幂等请求 |
| 请求结果不确定 | 界面保留并冻结原请求，使用原请求重试；后台可跨刷新、进程退出恢复已受理的提交 |

后台默认每 5 秒领取最多 20 条到期意图，租约 90 秒，最多 10 次失败后转人工处理；流程启动后约每 20 秒同步状态。强制退出进程后须等待原租约到期，页面状态允许短暂滞后。不得直接修改提交表、回执表或流程历史来“重置”操作。

## 升级与恢复

1. 升级前备份控制数据库及业务数据库，保存原镜像和配置；按既有表单/DNA 迁移顺序升级，本次额外执行 `20261014-workflow-operation-receipts.sql`、`20261014-workflow-business-links.sql`、`20261014-app-form-submissions.sql`。
2. 先更新授权服务，再更新调用服务。机器令牌须包含签名的 `client_id`、`grant_type=client_credentials` 与 `service-router.invoke` scope；APP ↔ Workflow 及 APP → DNA 使用明确的调用方白名单。
3. 存量业务命名空间通过 DNA 管理 API 准备快照基础表：先读取 `GET /dna/platform/dna/runtime/models/{modelId}` 的 `model.lockVersion`，再调用 `POST .../{modelId}/prepare-storage?expectedVersion=...`。仅授权管理员/治理恢复权限可调用，服务端解析 ACTIVE 版本并检查锁版本，不允许客户端指定任意版本。每个数据源/目录/Schema 选择一个活动模型即可。
4. 部署后逐一核对九个服务的镜像版本、JAR 校验和、容器健康和 Consul 检查。当前环境的受限发布目录保存数据库备份、旧镜像引用、变更源码及产物清单；备份和凭证不得提交到仓库。
5. 回滚前判断是否已有新提交：旧程序不具备新提交的恢复能力。优先使用兼容版本修复；如必须恢复数据库，应停止写入，并同时恢复匹配的控制面、业务数据和流程状态。不能只恢复一个数据库而保留另一侧的新事实。

## 兼容与容量边界

- 本轮验收覆盖 PostgreSQL 17、MySQL 8.4 的 DNA 主子事务与精确快照；当前环境完整跨服务和浏览器链路使用 PostgreSQL。其他目标数据库需按相同矩阵专项验收。
- 同一聚合在一个目标数据源事务中写入：最多 5 个明细集合，每集合最多 40 行，总计最多 200 行。超限明确拒绝。
- INT64、DECIMAL 的 HTTP 表示为精确字符串；流程内部使用 BigDecimal，条件表达式的数值常量同样保留十进制精度。禁止在外部集成中先转换为 JavaScript Number。
- 页面/流程版本固定，审批快照冻结。发布新版本不会自动迁移正在审批的实例。兼容结构升级由 DNA 发布治理检查，破坏性变化不自动执行。
- 跨数据源写入、分片/分批写入遵循用户确认的后续规划。当前不提供跨数据源事务保证，也不把轮询同步描述为事件推送。
- 模板市场、任意脚本计算/自定义动作及通用跨源关系不是本次业务审批闭环的能力声明。基础服务容量不等于生产峰值容量；部署方按实际峰值配置连接池、备份保留和监控告警。

## 重复验证

参见 [验收脚本说明](../../scripts/verification/README.md)。脚本使用正式 HTTPS 接口创建独立客户档案及巡检应用，校验记录更新、冲突、审批、精确边界分支并保留关联身份。每次运行创建独立数据，不覆盖业务数据。已受理命令的重放使用同一幂等键验证。
